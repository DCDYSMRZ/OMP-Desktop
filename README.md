# OMP-Desktop

本机已安装 **omp** 的桌面前端。沿用 PI-Desktop 原版中性深色基础呈现，根背景固定为 `#181818`，不提供主题或动效选择器。本轮「整体体验升级」统一导航、首页与输入、对话阅读、实时状态、子代理和设置：每个区域只承担一种职责，运行状态优先在回复位置呈现，离开视口后由浮动行接替。真实提交状态、异步归属和来源授权仍是基础；Agent 执行交给外部 `omp --mode rpc-ui`，不捆绑第二个运行时，也不修改 omp 本体。

**首次发行：** [v1.0.0（2026-10-07）](https://github.com/DCDYSMRZ/OMP-Desktop/releases/tag/v1.0.0) · [下载 Apple Silicon DMG](https://github.com/DCDYSMRZ/OMP-Desktop/releases/download/v1.0.0/OMP-Desktop-1.0.0-mac-arm64.dmg)。仅提供 macOS arm64，未签名、未公证；安装步骤见下文。

- 原生会话、流式消息、输入/审批、发送与停止；每轮依次为用户消息、过程、答复、后续更新和页脚。运行时仅过程与最新文字尾部流式呈现，收敛后才划分答复；耗时扣除等待用户的时间，问题数按最终结果计算。页脚显示本轮 tokens/费用，用量弹层列出逐请求与子代理合计。可写保存会话直接显示输入框，归档、历史节点和外部占用保持只读。
- 共享 omp 的配置、认证和文件会话；设置分为桌面端、omp 与关于，高级项有 16 个中文分类和 122 个整理标题，原生说明标注「omp 原文说明」，模型角色与服务商可搜索。无可用模型时可「在终端中登录」并重新检查；凭据始终由原生管理。在场扩展默认开启、可关闭，仅管理自己的扩展文件。
- 输入区内联显示计划、上下文与花费，未取得费用前隐藏花费；窄时依次收起花费、计划文字和上下文百分比，低于 600px 使用「…」溢出入口。金额统一为低于一美分的 `<$0.01` 或带千位分组的两位小数。终端持有时使用紧凑只读栏及「派生为新会话」。
- 顶部显示「项目 / 会话标题」与至多一个可点击状态提示；项目按最近活动排序，项目内置顶优先。侧栏当前项目显示至多 8 行、其他项目 5 行，可展开其余；共享分钟时钟显示紧凑相对时间，派生行注明父标题。受理首条消息同帧出现会话行，只淡入不位移；底部仅设置与来源问题摘要，「打开会话文件…」移入命令面板，omp 版本移入关于。
- 「派生为新会话」只读原来源，不受原会话占用影响，会话右键菜单与适用的只读栏均可进入；无需确认，成功带上草稿，失败原位提示。仅带入目前已保存内容，不跟随原会话后续进展。模型/思考标签立即更新，后台提交失败回滚；思考等级按当前运行时公布值校验，包含原生支持时的 max/inherit。
- 参与在场扩展的终端进程提供精确占用和活动，不再标「推断」；桌面可在落盘前显示当前工具及助手文字/思考，随后与保存消息对账不重复。扩展使用内核共享咨询锁和本机只读 Unix socket，不暴露提示词、工具参数或输出，也不提供控制命令。安装前已启动的进程仍用标注的启发式推断；陈旧/未知不等于完成，socket 超时不当作空闲。
- 类型化工具输出按字面呈现，完整输出优先可读标题与高亮内容，技术数据收入详情；用户图片标记显示可预览芯片，选择复制仍为原文。文件对象支持行范围预览、编辑器、快速查看和拖出，预览仍是「当前工作区版本」。本轮改动默认每文件一份最终净结果与 diff，改回原样不计入，不累加中间步骤；「过程与来源」按需展开。无需 Git，始终结合哈希、有界内存内容与已授权主/子工具证据；哈希确认变化但内容不足时仍列出文件、明确未知行数。当前 Git 工作区审阅单独标注，不提供快照回滚。
- 子代理名册以同一份对账证据汇总「委派 N 个子代理 · a 运行中 · b 已完成」，行内显示任务、当前步骤、状态与耗时；同代已确认终态不被模糊证据降级。子面板保留面包屑、单行累计指标、一处任务说明、过程及一份报告，真实祖先关系与授权分页不变。
- 工作面板以「文件 / 更改 / 任务 / 会话」分工，文档标签留在目的地内；检查器保留单一活动卡，策略默认收起。消息受理后，用户消息下方立即显示「正在思考 · N秒」，随后切换运行过程标题，当前章展开、文字在下方流式呈现。仅该标题滚出视口时，底部状态行才浮在输入区上方，不移动输入框或改变对话高度；120ms 淡入淡出，减少动态效果为 80ms。返回最新恢复跟随且不重复加载流式历史。
- 答复与推理按完整字形渐进出字，等待上限 250ms、流结束后 120ms 内排空，逐字 220ms 透明度淡入；代码、数学与表格不逐字淡入，历史/替换/减少动态效果立即显示。页面滑动跟随、落后至多 64px，恒定预留 108px；返回最新两屏内 300ms 追向实时底部，更远或减少动态效果时立即跳转，任何用户滚轮/触摸/键盘/滚动输入立即中断程序运动。
- 最新可读流式「思考」自动展开为至多 168px 的框，标题随摘要/最新段落更新，框内跟随底部；长满后仅框内滚动，外层页面保持不动。下一部分开始或结束 600ms 后收起，手动选择保留；保存/结束思考默认收起，展开为自然高度全文。实时委派名额未关联子代理时显示「等待中」，不误报未知错误。
- 首次发送复用预连接，连接或准入检查中按 Enter 仅待发送一次。运行中输入由桌面持有队列，不交给原生 follow_up；可立即插入、停止并发送、编辑或删除，收敛后发送下一条，Stop 暂停队列且不会随后自动发送。原生 ask 在对话内回答，输入框保留焦点与草稿，等待时可编辑但禁发送；等待/服务商重试在回复位置显示，标题离开视口后由底部浮动行接替，最终失败只保留一个本地化错误卡。
- 可证实的迟到任务交付归回原委派；混合 task/bash/eval、图片、诊断与残余内容不丢失。未知归属保持中性会话活动，不靠名称/位置猜测，不把错误或未知改成成功。原生上下文、恢复与未来可见类型保留自己的作者、生命周期和交互。
- 手动展开、焦点/选区与阅读锚点优先；主/子会话显示部分历史和来源限制，历史窗口返回最新会读取最新页。历史视图按路径/分支/锚点缓存至多六份，切换大会话不把旧窗口误报为新来源不可用；临时预览与状态有界。
- Cmd/Ctrl+K 统一会话、消息、文件、命令、设置和动作检索，空查询优先当前项目最近会话；消息检索覆盖工具参数/结果，不含附件、sidecar 与思考，部分覆盖明确提示并可转当前会话完整搜索。同会话重复片段合并为「N 处」，跨会话不合并。Cmd/Ctrl+F 分块查找已加载对话，代码高亮在模块 worker 中执行。
- 首页为居中的项目提问、同一输入框与三个安静建议；缺少条件才显示按依赖排序的配置卡。草稿约在启动 0.5 秒后只读预览原生配置默认模型，连接中禁选，真实模型以 120ms 交叉淡入接替；模型名称按实时目录、持久目录名称、id 统一解析。首发以 240ms FLIP 将输入框归位，导航与面板切换不滑移、不留残影。
- 动效统一为状态 120ms、折叠/浮层 180ms、面板/首发输入框 240ms、大表面 320ms；系统减少动态效果时无空间运动，仅 80ms 透明度交叉淡入且关闭流式字形动画。键盘日常路径无焦点陷阱，Esc 恢复菜单/面板/对话框焦点，礼貌播报仅报告状态变化；minimap 少于三轮隐藏，标记有名称并可键盘访问。
- 不包含 PI runtime、Rust host、插件市场、调度器、远程/云功能或独立权限策略。

## 下载与安装 v1.0.0

1. 在 [GitHub Release v1.0.0](https://github.com/DCDYSMRZ/OMP-Desktop/releases/tag/v1.0.0) 下载 `OMP-Desktop-1.0.0-mac-arm64.dmg`。此包仅面向 **Apple Silicon（arm64）Mac**，不是 Intel 或 universal 版本；其他平台不在首次二进制发行范围内。
2. 打开 DMG，将 `OMP-Desktop.app` 拖入「应用程序」（Applications），复制完成后推出磁盘映像，从「应用程序」启动。
3. 本发行版**没有 Developer ID 签名，也未经过 Apple 公证**。若首次打开被 macOS 阻止，仅在核对下载来源并决定信任此应用后，打开「系统设置 → 隐私与安全性」，在该应用的拦截提示旁选择「仍要打开」（Open Anyway），按系统要求认证并再次确认「打开」。不同 macOS 版本的提示文字可能不同；受管理设备的策略可能不允许此操作。若提示恶意软件或文件损坏，停止打开并核对来源，不将所有警告都当作正常未签名提示。
4. 应用启动后仍需本机独立安装、配置并认证 **omp**，见下方前提。打包应用自带 Electron，不要求另装系统 Node.js 或 pnpm；外部 omp 及其工具链仍须满足各自依赖。

不要全局关闭 Gatekeeper、批量/递归去除隔离标记或禁用 Electron 沙箱。以上是用户自行批准可信应用的操作说明，不是下载隔离/Gatekeeper 流程已经实测通过的声明。应用没有自动更新器；后续版本需从 Releases 手动下载。

## 前提

1. **仅源码开发/构建需要** Node.js **>=22.19.0** 与 **pnpm 10.34.5**。已打包的 Electron 应用本身不要求另装系统 Node/pnpm；外部 omp 的安装发行方式及它调用的工具仍有各自的运行依赖。
2. 本机独立安装 omp，并配置真实可用的模型/认证。接口适配基于 omp **18.3.2**；启动还要检查原生 RPC 能力，不能仅靠版本号认定兼容。
3. 本地可访问的项目目录。Git 用于差异面板，不是启动聊天的前提。模型服务商、原生工具/扩展各自的外部依赖由 omp 环境提供。

已有 omp 不需要重新安装。没有时遵循 [oh-my-pi 官方安装说明](https://github.com/can1357/oh-my-pi#install)。macOS 可选：

```sh
brew install can1357/tap/omp
omp --version
omp setup
```

没有可用模型时，首页与设置「提供商与凭据」显示「还没有可用的模型」，可点「在终端中登录」启动同一 profile 的 `omp login`，登录后点「重新检查」或切回窗口自动检查；也可在终端 `omp setup` 或原生 `omp` 中完成 `/login`、`/model`。API 密钥环境变量须由实际启动环境提供，不使用占位密钥或桌面自建认证库。

## 安装项目依赖与开发

首次获取对应发行源码可执行以下命令；已有源码时直接进入项目根目录。命令仅安装桌面依赖，不安装或更换 omp：

```sh
git clone --branch v1.0.0 https://github.com/DCDYSMRZ/OMP-Desktop.git
cd OMP-Desktop
npx --yes pnpm@10.34.5 install
npx --yes pnpm@10.34.5 dev
```

已有项目锁文件时，复现安装可以使用 `install --frozen-lockfile`。首次安装需要访问包仓库与 Electron 下载源；不要跳过必要的 Electron 安装脚本或禁用 sandbox 来掩盖缺失二进制。已安装正确版本的 pnpm 时，可将 `npx --yes pnpm@10.34.5` 简写为 `pnpm`。

项目根 `postinstall` 调用 `install-electron` 下载 Electron 二进制。当前 Electron 43.7.5 npm 包自身不再声明 postinstall，因此 `pnpm rebuild electron` 不能代替安装器。如果先前跳过了脚本或下载未完成，确认网络可用并清除 `ELECTRON_SKIP_BINARY_DOWNLOAD` 后恢复：

```sh
unset ELECTRON_SKIP_BINARY_DOWNLOAD
npx --yes pnpm@10.34.5 exec install-electron
```

该恢复命令仅安装项目 Electron，不安装 omp。不要以手工构造空 `dist/`、复制不匹配版本二进制或禁用安全特性代替成功下载。

首次打开后选择工作区；若 GUI 环境找不到运行文件，在设置中选择真实 `omp` 可执行文件。桌面与终端应使用相同 profile 和环境。全局配置修改会影响终端 omp，凭据仍由原生管理。

需要隔离桌面偏好时，可将环境变量 `OMP_DESKTOP_USER_DATA` 设为专用目录的绝对路径；它只隔离 Electron userData，**不会自动隔离 omp 配置/认证/历史**。原生隔离仍需单独设置临时 HOME/profile 及其环境。不要在实际用户数据上运行写入性验收。

## 检查、构建与预览

```sh
npx --yes pnpm@10.34.5 typecheck
npx --yes pnpm@10.34.5 test
npx --yes pnpm@10.34.5 e2e
npx --yes pnpm@10.34.5 build
npx --yes pnpm@10.34.5 preview
```

`build` 使用 electron-vite，输出到 `out/`；`preview` 启动已构建的 Electron 应用，不是打包后的安装包。`test` 执行仓库中维护的 TypeScript 行为回归。类型检查、单元回归、构建、实际 omp 场景、Electron 窗口和打包产物启动是不同证据，不能相互替代。

`pnpm e2e`（`bun e2e/run.mjs`）是独立于 `pnpm test` 的 macOS 日常路径套件，共 17 个场景：冷启动、立即发送、流式跟随、minimap 跟随、完成、并发、保存空闲、思考、删除、终端、设置、服务商错误、ask、首 token 较慢、查找后立即输入，以及 `thinking-live`（实时思考展开/内层跟随/收起）与 `thinking-kept`（结束/保存推理保留）。每场景独立 HOME/userData，沙箱拒绝真实 `~/.omp` 与非 loopback 网络，本机 fixture/真实 PTY 提供模型与终端覆盖。支持 `--scenario`、`--size`、`--locale zh-CN|en`（默认 zh-CN）、`--app <dir>`、`--out`、`--fixture-port`、`--cdp-port`；检查滑动跟随与严格性能预算，只清理自身废纸篓日志，不在真实用户数据上运行。

## 构建 macOS DMG 与目录包

### Apple Silicon DMG

在 Apple Silicon Mac 上，按上文安装源码构建依赖后执行：

```sh
npx --yes pnpm@10.34.5 run dist:mac
```

已安装 pnpm 10.34.5 时可使用 `pnpm run dist:mac`。脚本先执行现有 `pnpm build`，再调用项目锁定的 electron-builder，以 `--mac dmg --arm64 --publish never` 生成 `release/OMP-Desktop-1.0.0-mac-arm64.dmg`，并关闭签名身份自动发现。确定的文件名不表示每次构建的字节或校验和相同。此命令不自动发布到 GitHub，不使用发布凭据；保持未签名、未公证，不生成 Intel/universal 发行包。

对应源码使用 [v1.0.0 标签](https://github.com/DCDYSMRZ/OMP-Desktop/tree/v1.0.0)，保留锁文件、构建配置与许可材料；本地修改后可用相同构建步骤重新生成应用。实际 DMG 校验和与启动范围以 [验收记录](docs/VERIFICATION.md) 中该产物的观察为准，目前待发布验证补充，不能使用下方旧目录包的哈希代替。

### 未签名本地目录包

```sh
CSC_IDENTITY_AUTO_DISCOVERY=false npx --yes pnpm@10.34.5 run pack
```

必须使用 `run pack` 调用本项目脚本；`pnpm pack` 是包管理器自身的 npm tarball 命令，不是桌面打包。上面的环境变量在 macOS/Linux shell 中关闭签名身份自动发现，不使用个人签名身份或发布凭据。

此脚本先构建，再调用 `electron-builder --dir --publish never`，将当前宿主平台的**未打包目录形式应用**输出到 `release/`。平台/架构对应子目录由 electron-builder 决定；macOS 的目录中包含 `OMP-Desktop.app`。它不是 DMG/PKG/NSIS 安装器，也不是发布或上传命令。应用内包含 Electron 与前端，不包含 omp 可执行文件、用户认证或原生历史。目标机器仍需另行安装和配置 omp。

## 数据、安全与限制

- 通常使用 `~/.omp/agent` 的原生配置与会话，但 profile、环境变量和 XDG 根目录可能改变位置。桌面偏好单独存于 Electron `userData`；历史临时 SQLite 只存可丢弃元数据，不是第二套 Agent 会话权威存储。
- 旧桌面偏好读取时仅丢弃退役的 `theme` 与 `motionMode`，其余偏好仍严格校验并保留；返回与新保存的数据不含这两个键，公开更新接口拒绝它们。此迁移不修改原生 omp 配置、认证或会话。
- 历史检索与正文读取不自动恢复或请求模型；可写保存会话连接前显示记录模型/思考，打开选择器才连接，发送复用，历史节点只读。消息搜索有范围、耗时和来源边界，不覆盖未登记目录或未落盘内容。
- 空白/预分配路径不等于已保存会话；已知 owned 未落盘会话使用运行时视图，历史/树入口须有持久来源。曾保存来源丢失显式不可用，不冒充新建。输入聚焦使用圆角外框，编辑区不再叠加方形焦点阴影；按钮/菜单仍保留独立焦点提示。
- 保存会话按可写性显示输入框或只读栏；外部持有阻止写原会话及删除，但不阻止可派生来源创建新会话。桌面自有运行时准入不做全机探测，共享来源先检查在场锁，仅未参与进程使用缓存 10 秒的 ps/lsof；空闲无周期进程探测，目录在场事件与窗口聚焦驱动刷新。连接发布即授权可信原生来源（含未落盘预分配路径），列表授权规范化；任意 renderer 路径仍被拒绝。
- 来源级移除与 Disconnect 分开：会话记录和可证明独占的附属文件（子代理记录、生成文件）移到系统废纸篓，可在访达「放回原处」。缺失工作区不再阻碍附属文件移除，共享、占用中或无法证明独占者仍保留并逐项解释，可在访达显示；路径/ID 收入详情。外部持有仍阻止删除，多项 Trash 不原子，没有应用内一键撤销。
- 「在终端 omp 中启用会话在场信号」默认开启，将受管理的 `omp-desktop-presence.ts` 安装到 `<agentDir>/extensions/`，关闭会移除。设置显示版本和参与/未参与进程数；终端须安装后启动才参与，桌面运行时始终通过 `-e` 加载随包扩展。本机 socket 只提供状态及助手文字/思考，不暴露提示词、工具参数或输出。
- 错误统一显示本地化原因、已知时的具体建议与按需技术详情；未知原生错误保留「omp：原文」，不展示 IPC 前缀。运行时崩溃只显示一个可「重新连接」的通知，保留未发送草稿；历史/来源错误限定在当前视图并在导航后清除。
- 文件面板只读；本轮最终净结果与当前 Git 工作区状态分开，哈希区间变化不证明独占作者。捕获是有界 RAM 优先、压力下保留哈希的观测，不写磁盘快照或溢写缓存；不承诺操作系统零 swap 或全项目覆盖。重启/淘汰后与外部旧轮次从完整原始历史分段读取相关工具证据、逐项归约净结果，不因累计历史长度停止；载荷仅在 RAM 中处理，已有可丢弃元数据索引保留。可选过程明细的 256 步 / 1 MiB 展示上限不影响最终证据收集。未知不冒充零，真实证据缺失或单个 patch/diff 运算边界仍需说明，不补造历史端点；不是 PI 每工具快照，没有假回滚。详见使用说明。
- 任意原生 TUI 组件不能通过 RPC 完整显示；需要终端交互的扩展或首次认证应回到原生 omp。
- 渲染器沙箱不等于 Agent 工具沙箱。omp 使用当前用户权限；工具可能修改文件、运行命令、联网并产生费用。停止不能撤销已经执行的操作。
