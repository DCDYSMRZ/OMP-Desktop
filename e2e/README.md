# Desktop daily-path E2E

Run against the **existing** `out/` build; the suite never builds or edits application source. Requires macOS, Bun, installed `omp`, Python 3 (standard-library PTY only), and installed Electron dependencies. No browser automation dependency is added.

```sh
pnpm e2e
pnpm e2e -- --scenario live-follow --size 1440x900 --out /tmp/my-e2e
pnpm e2e -- --locale en --app /tmp/MyBuild/app --scenario saved-idle --fixture-port 19850 --cdp-port 19851 --out /tmp/my-e2e
```

Scenarios: `cold-launch`, `find-immediate`, `immediate-enter`, `live-follow`, `minimap-follow`, `completion`, `concurrent`, `saved-idle`, `thinking`, `thinking-kept`, `thinking-live`, `delete`, `terminal`, `settings`, `provider-error`, `ask`, `slow-first-token`. Each gets a fresh app, HOME and localhost provider; failures do not prevent the remaining scenarios. `--fixture-port` and `--cdp-port` default to 19750/19751. Do not run suites on the same ports concurrently. Output defaults to `/tmp/E2EHarness-evidence/<timestamp>-<size>`.

`--locale zh-CN|en` defaults to `zh-CN`. Expected UI labels come from the application's own locale initializer and catalogs, including ordered overrides. `--app <dir>` defaults to this repository and launches that directory's package entry; a safe build from `/tmp/omp-safe-build.mjs` is supported without rebuilding or modifying `out/`. Structural selectors remain only for transcript/sidebar geometry; actions use roles, accessible names and data-state where available.

`results.json` and individual scenario JSON files contain assertions, timing, warnings and PNG paths. Every PNG has matching visible text and element rectangles. Streaming rAF p95 must stay below 20 ms; tasks above 100 ms fail, 50–100 ms are reported. B5 requires painted following gaps ≤64 px and settlement to ≤1 px within 350 ms after bottom-target growth. Unclamped scroll velocity must be ≤1.45 px/ms (24 px per 16.7 ms); visibility-clamp frames may move no farther than their content growth. Movement p95 must be ≤12 px. Content shrink, viewport resize and explicit snaps are exempt. Assertions remain strict when the current app fails.

Painted follow uses a post-layout `ResizeObserver` after the application's observer, with an offscreen contained sentinel to sample every frame even after content stops growing. Samples retain scrollTop, delta, gap, growth age, following/user intent, explicit large-insertion snaps and return transitions. B3's 300 ms return tween is measured separately from steady B1 follow; its first bottom sample must arrive within 400 ms. Checkpoints read fresh frame samples. CDP screencasts retain five glide images and the first compositor image after the worst following gap; JSON retains consecutive frame measurements and compositor timestamps.

Controls are activated through their normal DOM focus/click handlers over raw CDP; typing, Enter and wheel input use CDP input events. No app IPC or internal store mutation is used. This suite checks visible behavior, not native pointer hit-testing. Renderer animations are left enabled.

`find-immediate` sends native Cmd+F and inserts the query immediately, without waiting for the find surface to mount. It verifies that typing reaches the focused find input and that the native answer yields exactly one match.

`minimap-follow` creates three overflowing native turns, checks the newest minimap marker during streaming and at idle, scrolls to the first marker, returns to latest, opens/closes Cmd+F, and resumes the saved journal with another streaming turn. Bottom/following always selects the newest marker; reading selects the entry at 30% of the viewport (the first marker at the very top). The same painted-follow, rAF and long-task budgets apply. Screenshots include idle/streaming bottom states and saved-session continuation; run with either locale catalog and `--size 1440x900` or `--size 1100x800`.

`slow-first-token` requires an accessible in-place “Thinking” header directly after the accepted user message before any provider token, with a nonzero active-time clock and no empty chapters. Its floating counterpart is hidden while that header intersects the thread viewport; the polite announcement region remains mounted. `live-follow` requires the floating row above the composer once the long report moves the header outside the viewport, checks identical composer top and transcript clientHeight with the overlay shown/hidden, and verifies clicking it resumes bottom following. Both enforce B5's painted glide, settlement, frame movement and return budgets. The floating row fades in/out in 120 ms (80 ms with reduced motion), over a constant 108 px transcript bottom reserve (72 px clearance plus the 36 px row), rather than resizing the transcript.

`minimap-follow` waits for the in-place running header, not for the floating row: short turns need no duplicate status above the composer. Its idle return-to-latest control remains available while reading earlier messages. `terminal` likewise waits for the running header to disappear at completion; floating-row visibility is not a completion signal.

`live-follow` records chapter `aria-expanded` changes in `live-follow-chapter-motion.json`. While following with no user input, each finished chapter must collapse within 400 ms of the next chapter starting. A native wheel burst during the final report must still defer automatic process collapse until scrolling stops, then allow it within 400 ms. Programmatic transcript/return/thinking-box scroll writes are identified by element and browser-read-back position; neither the global spatial-motion guard nor FLIP interprets them as user scrolling.

Native wheel points in `live-follow` are chosen from the visible intersection of `.thread-content` and its scrollport, not from a guessed edge offset. Every dispatch checks `document.elementFromPoint` still belongs to the transcript content and not an inner scrolling surface; blocked targets fail with coordinates and the receiving element. `live-follow-wheel-targets.json` records the selected points. This keeps compact-width resize handles out of the input path.

`thinking-kept` streams readable `reasoning_content` through the native provider adapter. It verifies the same in-place header from acceptance through settlement, a collapsed thought row directly above the answer (no empty chapters), ordered reasoning on expansion, and identical labels/text after disconnecting and reopening the native journal. Use `--size 1440x900` or `--size 1100x800`; all existing performance budgets remain unchanged.

`thinking-kept` records answer arrival, completion, and the header's `aria-expanded` flip in `thinking-kept-timing.json`. It waits at most 1500 ms after completion and requires collapse between answer + 550 ms and `max(completion, answer + 600 ms) + 150 ms`; tool-chapter timing is unchanged.

`thinking-live` streams a 28-paragraph native reasoning block. Post-layout ResizeObserver frame samples enforce the 168 px viewport including 12 px bottom padding, 12 px inner lag, newest-line visibility inside the scrollport, 13 px / 1.6 typography, top fade after scrolling, and a stationary outer transcript once full. It checks automatic expansion, collapse within 900 ms after answer start (600 ms grace plus 180 ms motion), settled duration/full natural-height expansion, inner user-scroll pause/resume, persistent manual collapse, and exactly one answer heading. Five screenshots cover live growth, the full masked box, auto-collapse, and settled closed/open states; run at 1440×900 and 1100×800. Raw samples, including newest-line and scrollport-bottom coordinates, are saved as `thinking-live-frames.json`.

Inner follow resumes only on downward user movement within 8 px of the bottom from the latest input's painted layout. Growth between input and `scroll`/`scrollend` is subtracted before deciding, so streamed paragraphs cannot strand the reader above the bottom. `thinking-live-scroll-intent.json` retains wheel/scroll/scrollend geometry; duration assertions use the application's locale formatter.

## Isolation and cleanup

The launcher uses the Electron **package entry**, a short temporary HOME, fresh userData, and a scrubbed environment. macOS sandbox-exec denies real `~/.omp`, real Application Support and all non-loopback network, including for spawned omp/tool children. It refuses non-macOS execution rather than silently dropping isolation. `/bin/ps` alone uses the same sandbox exception as the original `/tmp/omp-live/control.ts`. CDP attachment verifies the renderer package URL and listening process userData.

The provider is ported from the live fixture: simple/slow answers, native ask, HTTP 500, and real tools plus three subagents, intentional exit 7 and a long Markdown report. Saved-session coverage creates an actual native journal, disconnects it and reopens it; no synthetic journal or real user session is needed. Terminal coverage resumes a fixture-created journal in a real controlling PTY, not an RPC substitute; startup onboarding is disabled through native configuration. The reasoning model advertises native effort levels including `max`.

The HTTP 500 scenario disables native provider retries in its isolated configuration so the suite can assert the settled, actionable error instead of matching a transient retry countdown. Removal selects the currently offered localized delete/discard action, but still requires the finished journal to reach Trash and the settled result to be toast-only.

Finally/SIGINT/SIGTERM cleanup stops only recorded process trees, deletes the temporary HOME and records/removes only Trash journals whose session-header cwd equals this run’s temporary workspace (normalizing macOS `/private/tmp` to `/tmp`). Native title preambles are handled. Companion folders are cleaned with their verified journal. `trash.json` is the audit trail. SIGKILL cannot execute cleanup; `isolation.json` records the abandoned root for manual recovery.
