# OMP-Desktop 使用说明

## 1. 桌面与运行时

OMP-Desktop 是已安装 **omp** 的 Electron 前端，不包含 Agent 内核。主进程直接启动本机可执行文件，以 `omp --mode rpc-ui` 的原生 JSONL 协议通讯；不是 PI runtime、远程服务或第二套工具执行器。

模型请求、工具、MCP、Skills、扩展、subagent、认证和会话持久化属于 omp。窗口、固定基础配色、字体、布局、文件预览与受限 IPC 属于桌面。桌面不提供 PI 插件市场、计划任务、PR 工作流、远程主机、云同步、独立提示词增强或自定义权限注入。保留的原生 omp 扩展能力与被移除的 PI 桌面插件系统不是同一件事。

当前协议适配基于 omp 18.3.2 的接口。版本号相近不代表协议兼容；安装与窗口实测状态见 [VERIFICATION.md](VERIFICATION.md)，不能把本文操作说明当作已通过验收的证据。本文引用的 2026-09-30 / 2026-10-01 观察对应发布前阶段及旧目录包，不证明 v1.0.0 DMG 已通过相同场景。2026-10-07 的 DMG 已完成校验与只读挂载，复制出的 1.0.0 arm64 应用在保留原生沙箱的隔离环境中启动，使用真实外部 omp 与本机 loopback 模型 fixture 完成一条消息、收到预期答复且无警报；具体产物身份及限定范围见上述验收记录，不代表下载隔离/Gatekeeper 批准流程、商业服务商/OAuth、Intel 或全功能矩阵已经验收。

桌面恢复 PI-Desktop 原版中性深色基础呈现，根背景固定为 `#181818`；没有桌面主题、材质或动效选择器，也不再使用熔岩/黑曜石/玻璃材质、光学场景或弹簧指示器。正文与子代理卡片按内容正常排版，保留原生窗口 vibrancy、菜单/弹窗交互和系统“减少动态效果”支持。原生状态以文字和图标呈现，失去观测时显示未知/不可观测，不从旧快照推断仍在运行，也不推断成功或失败。

固定深色是此前回退选定的基线。本轮统一侧栏导航、头部位置与状态提示、主列阅读与回复位置的运行状态、离屏后的浮动兜底、输入区写作与用量、工作面板检查及浮层操作，各区域不重复承担同一状态。范围见 [当前验收：整体体验升级 — 2026-09-30](VERIFICATION.md#当前验收整体体验升级--2026-09-30)；[会话流程、实时阅读、步骤说明与删除 — 2026-09-29](VERIFICATION.md#历史验收会话流程实时阅读步骤说明与删除--2026-09-29) 及更早记录为历史证据，不将旧包或操作说明当作本轮全量 UI 重放证据。

## 2. 安装桌面、omp 与首次配置

### 安装 macOS 桌面应用

首个发行版为 **v1.0.0（2026-10-07）**，仅提供 **Apple Silicon（arm64）** DMG，不是 Intel/universal 版本。

1. 打开 [GitHub Release v1.0.0](https://github.com/DCDYSMRZ/OMP-Desktop/releases/tag/v1.0.0)，下载 [`OMP-Desktop-1.0.0-mac-arm64.dmg`](https://github.com/DCDYSMRZ/OMP-Desktop/releases/download/v1.0.0/OMP-Desktop-1.0.0-mac-arm64.dmg)。
2. 打开 DMG，将 `OMP-Desktop.app` 拖到「应用程序」（Applications），复制完成后推出磁盘映像，再从「应用程序」启动。
3. 此版**未经过 Developer ID 签名，也未经过 Apple 公证**。若 macOS 阻止首次打开，先核对来源；只有决定信任此应用后，才前往「系统设置 → 隐私与安全性」，在本应用的拦截提示旁点击「仍要打开」（Open Anyway），完成系统要求的认证并确认「打开」。系统版本与设备管理策略可能影响按钮或可用性。恶意软件或文件损坏提示不应直接视为普通未签名警告，应停止并核对下载来源。

不要全局关闭 Gatekeeper、批量/递归移除隔离标记或禁用 Electron 沙箱。这里说明正常逐应用批准流程，不声称已经完成下载隔离/Gatekeeper 的实机验收。应用没有自动更新器，新版本需从 Releases 手动下载。

打包应用自带 Electron，**不需要另装系统 Node.js 或 pnpm**。它不包含 omp、模型认证或你的原生会话；仍需按下节安装外部 omp，并满足该安装方式及其工具链自身的运行依赖。仅从源码开发/构建桌面时需要 Node.js **>=22.19.0** 与 **pnpm 10.34.5**，具体命令见 README。

### 安装外部 omp

已有 omp 时无需再次安装。先在普通终端确认：

```sh
omp --version
```

未安装时，按 [oh-my-pi 官方安装说明](https://github.com/can1357/oh-my-pi#install) 选择安装方式。macOS 可用：

```sh
brew install can1357/tap/omp
```

或者在已经安装符合上游要求的 Bun 后：

```sh
bun install -g @oh-my-pi/pi-coding-agent
```

安装 omp 与安装本项目的 Node 依赖是两件事。桌面不会自动下载另一个 Agent，也不会把 `pi` 当成备用运行时。

**首次没有可用模型时，使用原生终端完成配置。** 首页或设置「提供商与凭据」显示「还没有可用的模型」时，点「在终端中登录」会打开 Terminal，运行已解析的 `omp login` 并使用桌面配置的 profile；登录后点「重新检查」，或切回窗口自动检查。API 密钥环境变量提示仍需结合实际启动环境理解。原生非交互 `rpc-ui` 可能在 ready 前退出，不能依赖未启动的 RPC 完成首次登录；也可手动运行：

```sh
omp setup
omp
```

按原生向导选择真实可用的服务商、认证方式与默认模型；在原生会话中按需使用 `/login`、`/model`。API 密钥、OAuth 与自建服务商配置遵循 omp 自身说明，不要把密钥粘贴到桌面普通设置、诊断日志或聊天中。本地无认证模型是合法配置，但必须确实可以使用；不要填写虚构模型或占位密钥以绕过启动。某些 OAuth 服务商需要终端交互或秘密输入，也应在原生终端完成登录。

如果使用命名 profile，首次配置和桌面必须指向同一个 profile，例如：

```sh
omp --profile work setup
omp --profile work
```

桌面设置中的可执行文件应指向实际 `omp` 文件，不是 shell 命令、附加启动参数或 PI 可执行文件。Finder/Dock 启动的环境可能与终端不同；遇到找不到 omp 或工具链的问题，核对该路径、profile 以及启动环境，而不是重新创建一套凭据。

运行时发现会尝试恢复 login-shell 的 **PATH**，以找到本机 omp 与工具链；这不等于继承另一个终端中临时 `export` 的任意变量。Finder/Dock 无法自动获得该终端的临时 API key/代理/自定义服务商变量。使用原生认证、相同 profile 与原生 `.env`，或从需要的环境直接启动应用可执行文件；不要把 PATH 恢复误解成秘密变量同步。

## 3. 工作区与会话

1. 选择本地项目目录作为工作区。它决定子进程 `cwd`、项目级配置解析与文件面板边界。
2. 首页或「新建会话」显示草稿后即后台预连接，不恢复旧会话，第一条真实消息前不建会话文件。保存会话的可写最新分支直接显示输入框，归档、历史节点和外部占用使用对应只读模式；打开记录本身只读取历史。
3. 新草稿发送前可选择真实模型/思考，首次发送复用预连接。保存会话先显示记录的模型/思考，打开选择器按发送同样的准入连接一次，发送复用；未打开选择器时首次发送才连接。模型列表存在不保证每个模型的凭据有效。
4. 正在运行时，新消息先保存在桌面队列，不送入原生 follow_up；收敛后发送下一条。队列以单行 chip 显示至多三条，其余通过向上展开的全宽「还有 N 条」弹层查看；悬停或键盘聚焦可「立即插入」（原生 steer）、「停止并发送」（原生 abort_and_prompt）、「编辑」或「删除」。停止会暂停队列，不会在随后收敛时自动发送。
5. 停止按钮发送原生 abort；主动停止显示「已停止」及停止时的耗时，格式遵循「耗时格式」设置，保留部分输出，不弹红色错误或停止回执，被中断工具不计作红色失败。真实意外错误仍显示。停止不是撤销已经执行的写入、命令或外部请求。macOS 在本应用拥有的会话仍运行时关窗只隐藏，运行继续，Dock/activate 可恢复；Cmd+Q/菜单退出，或其他平台运行中关窗，会询问「有 N 个会话正在运行，确定退出吗？」，默认「取消」，确认「停止并退出」才关闭自有运行时。空闲关窗正常退出，不终止用户另开的终端 omp。

消息被受理、单次回复结束、全部后台任务结束是不同状态。命令 ACK 或 `agent_end` 不是会话完全静止的证据；原生 `session_settled` / `isSettled` 才描述完整收敛。断线、进程退出或错误后，不应假设最后一条消息未被处理，也不要无判断地重复发送有副作用的请求。

### 首页

首页显示居中的「今天想在 <项目> 做点什么？」、同一输入框和三个只填草稿的安静建议。首条消息发送后，输入框以 240ms FLIP 滑到固定位置；系统减少动态效果时立即归位。切换会话、首页与会话互切、开关工作面板都不会滑移输入框或留下残影。

准备卡只在缺少条件时出现，依赖顺序为：找不到 omp（「选择 omp」）、未选工作区、工作区已删除（「工作区文件夹不存在」，可「选择其他文件夹」或「从列表移除」）、没有可用模型（「在终端中登录」与「重新检查」）。真实连接失败仍在居中布局内显示重试卡，不以配置缺失冒充连接故障。

获知工作区后即后台预连接。约启动 0.5 秒后，草稿可先只读显示原生配置的默认模型，旁有「连接中…」，选择器暂不可用；按全局→项目→`PI_CONFIG_FILES` 配置层及实际 profile/环境解析，选择器有歧义时保持未知。真实运行时模型到达后以 120ms 交叉淡入替换，再可选择模型/思考。输入区、页脚、子代理指标与侧栏提示统一按实时模型目录→持久目录名称→id 取名，不猜名称。

连接中按 Enter 也会受理输入并显示待发送状态，就绪后只提交一次；启动失败恢复草稿并说明原因，失败的预连接在重新聚焦时重启。最多一个预连接草稿运行时，离开未发送草稿安静释放，不留侧栏条目或文件。

旧的只有头部的「未命名会话」文件来自桌面曾调用原生 `new_session`，该命令强制空 journal 落盘。现在以临时 `--config` 设置 `autoResume:false`，不发 `new_session`，使用原生延迟建文件机制，第一条真实消息前不落盘；已有空白文件仍按删除规则处理。

### 快捷键与命令面板

- Cmd/Ctrl+K 打开命令面板，范围为全部/会话/消息/文件/命令/设置/动作，支持 `>`、`/`、`@`、`#` 前缀、模糊排序和命中高亮。加载中保留稳定结果；宽窗口预览会话摘录、消息片段或文件前 40 行。选择命令只填入草稿，不自动发送；设置结果定位具体行。
- 空查询显示最近会话，当前项目优先；根文件保持一行，原生英文命令说明作为次要文字。侧栏不再提供「打开会话文件…」，从命令面板进入；历史消息的覆盖范围与合并规则见下文「查找与历史搜索」。
- Cmd/Ctrl+P 直达文件，Cmd/Ctrl+Shift+F 搜索历史消息，Cmd/Ctrl+F 查找当前已加载对话；`?` 或 Cmd/Ctrl+/ 打开快捷键帮助。键盘绑定、命令面板键帽、帮助和本地化原生菜单使用同一注册表；macOS 保留原生编辑与窗口菜单行为。
- 输入区命令按钮与 `/` 共用按来源分组的列表、本地化内置描述、参数提示和模糊排序；这是草稿输入入口，不绕过发送或原生准入。

### 通知与收件箱

收件箱按会话分组显示需要回复、失败、离开期间完成和子代理关注，可跳转、标为已读或全部已读；失败预览显示本地化原因。只有未读时才显示深色高对比徽标。已读不代替回答请求；当前对话的原生 ask 在正文内显示，方向键/Enter 回答，Esc 不关闭必答问题，头部状态提示可聚焦问题。输入框保持焦点和草稿，等待时仍可编辑，但发送被禁用并说明原因；回答后留下本地化回执。启动或其他会话的交互请求仍使用模态路径，不混入当前对话。

“通知”桌面偏好默认开启。窗口未聚焦或隐藏时，原生通知仅包含会话标题和简短状态，不包含请求正文；点击后显示窗口并选择会话。macOS Dock 显示需要回复的会话数，后台出现新请求时提醒一次；窗口标题同步“会话 — 项目 · 运行中”。这些提醒不代表额外执行权限。应用内 toast 保留信息/成功/警告/错误级别、会话及项目来源和“打开会话”，重复合并，最多三条同时显示，其余以数量提示。

每个会话始终位于所属项目，项目按最近活动排序，项目内置顶优先，其余按最近用户请求排序；运行、等待、失败和未读只作行内标记。当前项目最多显示 8 行、其他项目 5 行，再用「显示其余 N 个 / 收起」展开。相对时间共用分钟时钟，显示「刚刚 / 5分 / 3时 / 昨天 / 9/27」；派生会话带分支图标与「派生自『父标题』」提示。首条提交受理同帧出现会话行，只淡入不位移；运行与结束不搬家，选中展开项目并滚入视图。

会话行菜单为「置顶 / 重命名会话 / 会话历史与分支 / 派生为新会话 / 删除会话…」，自有运行时另有「断开连接」。任意已保存来源可派生，不可用时解释原因（例如未保存草稿）。侧栏底部只有「设置」和简短来源问题行（如「1 个会话无法读取 · 查看」）；omp 版本位于「设置 › 关于」。

侧栏、会话预览与首页共用优先级：**等待回复 > 失败 > 运行中 > 完成未读 > 无标记**。桌面自有运行时与参与在场扩展的终端提供精确状态，未参与进程才沿用标注为推断的日志/进程证据。运行点缓慢呼吸，减少动态效果时静止；历史/空闲无灰方块，没有标记不等于写入授权。

### 输入区会话状态与计划

输入工具栏内联显示**计划 · 上下文 · 花费**，尚无费用值时隐藏花费，不显示「统计中」。实时状态优先显示在回复位置，原位标题滚出视口后才出现底部浮动行，不与用量区混排。终端持有来源使用紧凑只读栏「其他终端正在运行此会话 · 只读」，附信息入口，右侧为「派生为新会话」。

**上下文是占用，不是累计 token 或本次输出。** 采用 omp 的提示锚点：`contextSnapshot.promptTokens`，缺失时为 input + cacheRead + cacheWrite，不含本次生成的 output。保存会话沿当前分支保留每次请求的上下文快照，失败或中断的请求不覆盖有效测量；实时以原生 `contextUsage` 为准，窗口为 0 时视为未知并回退到模型窗口。每完成一次模型请求后约 400ms 刷新，不逐 token 轮询。

14px 圆环按占用率填充，旁边为整数百分比，低于 1% 时保留一位小数。颜色取实际达到的最高等级：警告为 50% 或 150K tokens，紫色为 70% 或 270K，错误为 90% 或 500K。窗口未知显示虚线圆环和 token 数，不冒充 0%；压缩中显示旋转圆环，上次请求后发生压缩则标注「已压缩」，记录了压缩后 token 时显示该值。提示示例为「上下文 619.7K / 1M tokens · 62.0%」。

点击上下文打开大号百分比、带阈值刻度的进度条、已用/窗口、模型名称及窗口来源（运行时/模型目录/模型配置）。说明按实际达到的阈值给出，例如「已超过 500K tokens，模型效果可能下降；omp 可能会自动压缩上下文。」实时会话还显示自动压缩状态与「管理…」，保存历史注明有效测量来自的最后一次请求时间。

弹层以颜色区分系统提示、项目规则与环境、工具定义、技能、对话消息和可用空间，并明确标注为估算。实时会话显示五类构成，随状态更新系统提示与工具；**保存会话若没有 `session_init`，仅显示非消息估算与对话消息两类，不补造五类细分**。快照保留非消息 token、压缩代次与历史改写移除量；失败或中断请求不会覆盖有效测量。

自动压缩与提前准备刻度依据**当前配置**和模型能力计算，标注「按当前配置」、百分比与 token，而不是宣称重建了历史设置。配置经已有只读设置读取；无法判断时不显示提前准备刻度。保存历史的构成限制与当前配置标记应和占用数字一起理解。

保存会话的窗口先查各实时连接提供的 `get_available_models`/当前模型目录（带时间戳保存在 userData），再只读解析 omp 代理目录的 `models.yml`、`.yaml` 或 `.json`；仅保留模型能力信息，不保留或记录任何凭据字段，新增输入类型及远程压缩是否可用的布尔值，不导出远程 URL。此过程不启动 omp、不联网、不写配置。两者都不能确定时保持「窗口未知」，不臆造默认窗口。

**花费是整个会话的主会话助手用量 + 子代理用量，实时与保存会话定义相同。** 子代理优先使用 task 结果的 `details.usage`，缺失时沿已授权子会话来源递归读取，有深度/数量上限、环路保护且不重复计算；无法解析的明确显示「N 个子代理未记录用量」，不当作零。未落盘实时会话回退到 `get_session_stats`。全界面使用同一金额格式：低于一美分为 `<$0.01`，其余两位小数并保留千位分组，如 `$1,820.96`。弹层保留主/子拆分、输入/输出/缓存 token 与请求信息，不把未取得的费用显示为零。

**计划**显示清单图标与完成/总数；实时有进行中任务且空间足够时附带当前任务，如「并行调研三个模块 · 1/4」。全部任务结束（完成 + 放弃）时显示完成样式，受阻任务带提示点。点击向上打开计划弹出层，列出阶段、任务、受阻原因及明确的已放弃项，当前阶段展开；措辞区分「进行中」「计划」「来自保存的历史」「已暂停」。输入框上方不再常驻展开计划。

运行中子代理可从名单进入子面板，队列逐条操作留在 chip；底部状态行仅在原位运行标题离开视口时作为兜底，不常驻挤占输入区。

响应式以输入区容器宽度为准，依次收起花费、计划文字与上下文百分比，低于 600px 使用「…」溢出入口。模型仍保持可读，错误提示位于输入区块内部，不与附件或编辑器重叠。

会话面板依次呈现身份、单一活动卡（空闲/运行中等）、上下文、生成与花费；思考等级本地化，金额使用共享格式，策略默认收起。已有命令、写入守卫与回执语义不变。

### 提交回执不是聊天记录

新草稿首次发送复用预连接；连接中或会话准入仍在检查时按 Enter，会受理为待发送，待就绪且准入完成后只提交一次，连续两次 Enter 也不会重复发送。启动或准入失败保留草稿与原因，不绕过外部占用保护。受理后原生消息接替本地气泡，回执保留未受理、排队、错误与未知等事实，移除回执不撤销命令。

提交回执摘要使用中性的「提交记录与诊断」，不重复输入区唯一的排队数量提示；逐条待送达、失败与未知状态仍可查看。

发送绑定当时的预期 session ID，主进程在写入前发现会话已变则拒绝，不能把旧草稿误投给新身份。原生命令、进程内消息和 journal 条目属于不同 ID 命名空间，没有完整逐项对照；相同文字的两次输入也不能合并成一次。迟到的 prompt_result 失败会保留原始输入和错误，不被先前 ACK 当作成功遮盖；发送失败和并发编辑仍遵守原有草稿/附件保留规则，不自动重发。

**桌面排队不是原生已送达。** 待发项由桌面持有，Stop 暂停后不会自动发送；明确立即插入才交原生 steer。原生命令 ACK 仍只证明受理，不证明逐项送达，断线不能视为安全重试依据。回执总容量为 64，已完成/本地执行成功记录最多保留 12；活动、失败或未知记录不会为腾出成功保留空间被静默清掉，容量满会明确阻止新增回执。回执不承诺应用重启后恢复。

**预连接不等于已保存。** 新草稿已有原生运行时，但不恢复旧会话，也不在第一条真实消息前建文件；离开未发送草稿会释放运行时。以前已保存的空白来源或派生目标仍按真实持久状态处理，来源丢失不冒充未保存草稿。

### 打开、直接续写与派生

- **打开与查看：** 侧栏打开已保存记录先显示对话正文，占用/准入检查在后台完成；输入区和头部显示「检查中」，检查通过前不向运行时发送。界面按可写性决定输入模式，可写最新分支直接显示输入框，无需额外续写按钮；打开本身不执行恢复。历史菜单保留树、最新内容、父来源与来源详情，选中旧节点只改变阅读位置。
- **模型与直接续写：** 空闲保存会话先显示记录模型/思考，打开选择器按发送同样的准入连接一次，发送复用；只读模式禁用模型。重新打开后仍在检查准入时，Enter 将文字保留为「检查中」待发，结果就绪且允许后只提交一次；阻塞、外部占用或未知则保留文字与原因，切换离开取消等待。可重新检查或派生，不能绕过写入权限。纯来源说明留在详情，仅实质性问题作为对话提示。
- **续写时的后台读取：** 保存子代理发现期间若 journal 继续增长，会重试至多三次；仍无法完成时保留上次完整结果并给出诊断，不把正常追加误报成续写失败。自动后台刷新失败仅留在对应视图的诊断中，不弹通知或向对话插入错误提示。
- **外部占用与只读来源：** 终端持有时显示紧凑「其他终端正在运行此会话 · 只读」栏，附信息入口，右侧「派生为新会话」。归档来源只读并提供派生；查看历史节点只读，提供「回到最新」与派生。外部进程即使空闲仍持有原会话，不能发送、注入消息或强占，活动空闲不等于写入准入通过。
- **派生为新会话：** 会话右键菜单提供此入口，外部占用、归档与历史节点的只读区域也可使用。只要来源可派生即可操作，不要求原会话空闲或允许写入。点击直接开始，不弹确认框，按钮显示进行中；成功打开新会话并带上当前草稿，失败在原处说明并可重试。它基于**目前已保存的内容**创建新会话，原会话不变，其他终端之后的进展不会带入；不会因带上草稿而自动发送。原生 `--fork` 生成新身份，两个会话仍共享工作区文件。
- **权限分开判断：** 续写原会话仍受占用准入约束；派生只读来源，不沿用写原文件的限制。删除对外部持有与无法确定采用下方不同策略，不把所有操作都按一个可写标记开关。

改名与已接管会话的原生 branch 是明确的写操作，和只读树浏览分开。clear/压缩前的已保存正文仍可查看，但可见历史不等于全部内容再次发送给模型。桌面不提供 PI 快照回滚、任意历史节点删除或通用归档管理；整个来源的明确移除与分支浏览是不同操作。

### 其他终端的只读实时观测

参与会话在场扩展的终端显示精确的「其他终端正在运行」，不标「推断」，同时提供持续计时、当前工具及落盘前的助手文字/思考流。实时尾部随后与保存消息对账，不重复显示；socket 超时显示「运行状态未知」，不当作空闲。只读观测不提供向终端发送或控制进程的能力。

其他终端新建的会话会在约 0.3 秒内（目录通知去抖）自动出现在侧栏，最迟由每 5 秒一次的列表对账补上，无需重新加载窗口。外部会话运行中的耗时从请求开始持续计时，即使父会话暂时没有新记录（例如只有子代理在工作）也不会停住；判定为无新进展时，计时停在最后一次持久进展。

未参与扩展的进程继续使用明确标注的启发式观测：日志增量读取与活动 500ms/空闲 2s 对账，近期未选来源读取有界尾部并每 5s 对账。此模式不能显示尚未落盘的提供者文字，陈旧或未知不代表完成，也不能作为接管原会话的依据。

### 会话在场信号扩展与隐私

设置「在终端 omp 中启用会话在场信号」默认开启。桌面向用户 `<agentDir>/extensions/omp-desktop-presence.ts` 原子安装/更新无依赖扩展 v1.0.0，只覆盖带自身管理标记的文件；关闭设置会移除它。设置显示已安装版本及参与/未参与 omp 进程数，不修改 omp 本体。

omp 在 TUI、rpc-ui、print 和子代理中自动加载该目录的扩展；安装之后启动的进程才参与，之前已启动的进程保留推断路径。桌面启动的运行时始终通过 `-e` 加载随应用携带的扩展。

扩展为进程打开的主会话及运行中子会话持有内核共享咨询锁，切换、退出、崩溃或 SIGKILL 时系统释放。每进程本机 Unix socket 只读、权限 0600，提供在场/运行状态、当前工具和助手文字/思考；**不暴露提示词、工具参数或工具输出，不提供控制命令，也不改变 omp 状态**。扩展加载或处理异常被隔离。

桌面自有运行时准入不做全机进程探测；共享来源先检查在场锁，持有者不响应仍按外部占用保护。仅未参与进程使用旧 ps/lsof 启发式，缓存 10 秒。空闲时无周期进程探测，在场目录事件（包括稍后创建的目录）与窗口聚焦驱动访问状态刷新；设置的在场信息只在「通知与在场」可见时轮询。TUI 仍打开会话时即使没有生成也阻止删除，socket 超时不等于锁释放。



### 断开、丢弃与移到废纸篓

**「断开连接」只断开本应用拥有的运行时，不是删除会话。** 「移到废纸篓」作用于整个原生来源及保存分支，不是仅删除当前历史节点。从未保存过的桌面会话直接丢弃，不做占用探测；未发送的新建草稿离开后本就不留条目或文件。以前遗留的已保存空白会话仍使用废纸篓流程，任意缺失文件不能冒充丢弃成功。

- 确认框说明：「会话记录和它的附属文件（子代理记录、生成的文件）会移到系统废纸篓，可在访达的废纸篓中‘放回原处’恢复。」附属文件指该会话配套的子代理记录和生成文件，不是整个工作区；配置、认证、其他会话和共享文件不因此删除。确认前核对来源，执行中防止重复操作。
- 桌面持有的已保存会话先安全关闭原生连接，再移到废纸篓；关闭结果不安全时保留数据并说明。停止不等于删除成功，也不撤销工具外部副作用；关闭期间新落盘的来源按真实状态重新核验。
- 保存记录先移入系统废纸篓，再处理能证明独占且安全的附属文件。工作区文件夹已经删除时，会通过现存父目录解析，不再仅因工作区缺失保留附属文件夹；共享、仍在使用或无法证明独占的项目继续保留。不沿父会话或旧路径递归删除，也不把只读访问权当成删除权限。
- 已证实外部持有时阻止删除并说明「此会话正在其他终端中打开，关闭后再删除」，不终止外部进程。仍无法确定时，对话框说明原因并提供「仍要移到废纸篓」，只有明确同意才继续；废纸篓可恢复，但关联资源的独占性与安全检查不放宽。授权、身份、文件类型及替换风险仍校验，本应用串行化不等于跨客户端锁。
- 干净成功只显示「已移到废纸篓」提示。部分结果逐项用普通句子说明，例如「附属文件夹没有移走：另一个会话也在使用它」，并提供「在访达中显示」；路径和 ID 只在详情中。无效原生登记标记仍按既有规则跳过，删除只清理该会话自己的标记。
- **多项 Trash 不是原子事务。** 来源移动失败时不继续移走附属资源；来源已移动但附属资源或偏好清理失败时报告部分完成、保留路径与原因。已移除来源仍从当前会话状态清理，不因部分失败重新出现；来源保留时仍保留记录并显示失败，不能把已经停止的运行时说成仍在运行。切换到另一个会话后，迟到结果不清空新选择。
- 在访达打开系统废纸篓，对移走的会话记录及附属文件使用「放回原处」（Put Back）恢复，再刷新历史或打开恢复来源。仅恢复 journal 不保证附属文件也恢复，清空废纸篓后不承诺恢复；没有应用内恢复事务或一键撤销，不会在 Trash 失败时改为永久删除。

未参与在场扩展的进程才沿用目标限定的 ps/lsof/终端记录判断，无关证据不全局阻塞，相关证据缺失保持不确定。参与进程的内核锁优先证明持有；桌面运行时按应用主进程后代关系识别，检查末尾更新自有事实，不被自己的运行时阻塞。外部持有者即使 socket 不响应也不能通过「仍要移到废纸篓」绕过保护。

### 消息呈现、导航与输入

用户正文逐字显示，HTML 注释、标签和 Markdown 定界符不会被当作富文本语法吞掉；文字可选择复制，链接、文件引用与附件保留相应入口。原生标注为用户的 skill/collab 显示用户归属及实际类型，skill 的原始调用与扩展上下文区分；代理发来的任务分配不冒充你本地键入的提问。归属与开启新轮是不同判断：未知的用户归属上下文可以显示为用户活动，却不自动制造新请求；原生隐藏指令不进入普通对话。

用户正文中的 `[Image #N, WxH]` 标记显示为内联图片芯片，可点击预览；无法读取时显示「图 N · 不可用」，提示说明原因。选择和复制仍保留原始标记文字，不以芯片显示文本替换原文。

一次请求按**用户消息 → 过程 → 答复 → 后续更新 → 页脚**阅读。消息受理后，助手轮次立即在用户消息下方显示「正在思考 · N秒」，不必等首段输出；随后为「正在处理 · 用时 · N 章节 · M 步」过程标题，当前章展开，文字在下方流式呈现。等待原生 ask 时原位显示「等待你的选择」，服务商重试也在此说明。运行中尚不将文字最终分类为答复/后续更新，收敛后再整理，完成过程默认收起。

过程按叙述分章，步骤直接显示，连续至少五个成功读取/搜索步骤才合组。压缩保留章节标题，当前章为安静的 1px 轨线。最新可读且仍流式生成的「思考」行自动展开，本轮手动切换过该行时尊重选择。耗时从请求开始到收敛，扣除原生 ask 与明确审批/输入等待，实时与重开一致；等待标题为「等待你的选择」并暂停时钟，亚秒或未知不显示「0秒」。

实时标题为「思考 · 标题」，优先取最新独立加粗摘要段，否则取最新段落前 40 个字形，以 120ms 交叉淡入；实时行不重复耗时。正文 13px/1.6、弱化文字，框高至多 168px（约七行，含 12px 底部留白），悬停显示滚动条，滚后顶部淡化。框内 τ80ms 跟随、落后至多 12px，最新行完整可见；框长满后仅内部滚动。向上滚动暂停跟随；只有向下滚回距本次输入开始时的底部 8px 内才恢复，判断会扣除手势期间新增长的推理内容，并在滚动及滚动结束时检查。向上滚动不会恢复跟随，不会因为回复同时增长而将真正的返回底部误判为仍在读旧内容。

思考行在下一部分（答复或工具）开始或轮次收敛 600ms 后，以 180ms 收为「思考 · 标题 · N秒」；手动选择优先，程序内滚不延迟收起。仅有推理的轮次，整个原位标题在「轮次完成」与「答复开始后 600ms」两者较晚时只收起一次，保留「已思考 · 用时 N秒」；有工具章节的轮次维持原收敛行为。被隐去或不可读推理不自动展开，显示「思考 · 提供方已隐去推理内容」及耗时。结束/保存行默认收起，展开为自然高度全文，不使用内层限高框。

问题数按结果计算：已完成报告、已恢复操作、预期失败与用户停止不计作问题。失败轮次只显示一个本地化错误卡，已知原因给具体建议，未知原生错误保留「omp：原文」，提供「重试 / 打开设置」与按需「技术详情」；最终重试通知不重复出现，服务商重试在回复位置或其离屏浮动兜底中显示。用户停止为中性的「已停止 · 用时 N」，保留部分输出。

工具行显示图标、动作、对象、元数据和状态；命令/eval 运行时附四行输出尾部。仅有保存结果的行从原生结果元数据恢复对象，缺参数明确标注「参数未载入 / 参数未记录 / 正在接收参数…」，不留孤立动词。工具结果按字面显示，Markdown/纯文本读取结果换行，代码保留横向滚动；编辑按文件显示 diff，其他类型保留各自列表、来源或问答。复制、原始数据与完整输出集中在详情中，不重复错误堆栈。

步骤文字说明谁对什么做了什么、结果如何；术语统一为「子代理」「后台任务」「运行中」，详情仍可展开。例如：

| 场景 | 步骤说明示例 |
| --- | --- |
| 发消息/群发 | 给子代理 X 发消息：摘要 · 已送达 / 已唤醒并送达 / 未送达；给 N 个子代理群发 |
| 等待与读取 | 等待子代理的结果或消息 · X 已完成、Y 仍在运行；查看子代理 X 的结果 |
| 后台任务 | 查看后台任务 X；停止后台任务 X · 已停止；后台进程 X 退出（代码 N） |
| 计划 | 制定计划：N 个阶段、M 项；开始：项目；完成：项目 · a/b 项完成 |
| 委派与来信 | 委派 N 个子代理：A、B、C；子代理 X 发来消息：摘要 |
| 异步结果 | 收到 N 个后台结果：A 已完成、B 失败；不能确认的结果标为状态未知 |

旧 hub 的 send/wait、查看生成文件/本地记录/会话记录/工具说明、提交结果（yield）、请教顾问（advise）、设定目标（goal）、向你提问（ask）、工具设备及 MCP 调用也使用相应语义说明，而不是只有含混动词。

打开完整工具输出时，先显示可读标题（如 `edit · format-duration.ts`）与带换行的高亮内容；条目 ID、会话路径和原始 JSON 收在「技术详情」。技术预览上限为 64Ki UTF-16 字符，截断时明确标注，不将预览冒充完整来源。

各工具族的结果图片以延迟加载缩略图保留；浏览器/计算机步骤先展示动作、URL 和截图。编辑 diff 下显示原生对象、逐文件或旧格式诊断，带级别与 `path:line` 定位；图片读取占位本地化，不把传输包装文字当内容。图片查看器支持适应/100%、有界缩放和平移、尺寸、缩略图带与左右方向键；有授权本地路径时可在访达中显示，没有通用图片写入授权，因此不提供“保存图片”。缺失图片/资源在内容后合并为“部分附件不可用 · N 项”，不重复堆叠警告。

提供者片段不制造用户轮次，真实重复片段与错误部分正文保留；已恢复尝试不误报为新失败。答复正文 15px、代码 13px；**页脚仅轮次结束后出现**，默认始终显示，可在设置改为悬停显示。页脚为「时间 · 模型 · 本轮 tokens · 费用」，零用量隐藏，日期提示保留完整时间，模型名与金额使用全界面统一格式。原始记录菜单按序号、角色、时间与预览标注。

用量弹层先显示「总 tokens · 费用 · N 次请求 · M 个子代理」，再列「# · 输入 · 输出 · 缓存读/写 · 费用」及子代理合计。这是本轮口径，不是最近一次请求；输入区费用为整个会话主/子合计，二者不保证等同商业账单。用量表与原始记录列表仅打开时构建，关闭的页脚只保留轻量汇总，避免长会话每轮重复计算。菜单锚定按钮并避让窗口，支持键盘与 Esc 返回焦点。

迟到结果只有在授权子任务身份与原始 task 调用可核对时才归回原委派，即使中间已有新提问。混合交付可分属多个调用，task/bash/eval、图片、结构化输出校验/捕获错误和残余正文保留各自含义，不统一贴成“任务成功”。缺少调用、别名重复或所有权不明时按原顺序显示中性会话活动和原因，不按名称或距离分给某个任务；原始来源仍可访问。

压缩/分支/reset 是上下文边界；命令输出、执行/文件引用、诊断/advisor/IRC/启动完成/交接、重试恢复和中断有各自说明。未知可见类型先显示原生声明的正文或媒体及所属上下文，再提供有界技术详情，不自动标成助手答复。隐藏推理、签名和提供者回放只按其性质说明，不作为普通正文；完整持久记录和输出仍经授权来源/资源入口分段读取，技术预览不代表完整原文。无法定位的命令输出留作明确的会话输出，不挪到无关的后续答复中。

上下文压缩、分支摘要和交接默认是一行卡片，显示名称、单行摘要和 token 变化；点击或按 Enter/Space 展开为纵向摘要，长摘要限高内滚，可点“显示全文”；归档对话与原始详情按需展开。卡片顶部和底部都能收起，收起后标题留在原处；Cmd+F 命中摘要内文字时会自动展开定位。

展开可查看参数、结果与来源，手动选择优先，嵌套展开不因收起外层重置；焦点、选区与阅读位置保留。接近顶部自动加载上一页，只有真实起点才显示「已到会话开头」，压缩不是分页边界。翻页期间的后台更新合并到页面插入后应用，不取消旧页，失败后可再次触发。旧内容每帧分批插入六轮；即使较早页面使不完整轮次重新分组，首个可见消息仍保持原位（±1px），重新归位的 IRC 交付与回复会恢复准确的折叠路径，不因内容移入折叠区而丢失阅读锚点。历史窗口返回最新读取最新页，失败或被新选择取代时保留原页；流式最新窗口仅回到底部，不重复读历史。

每次旧内容提交都以正在阅读的文字片段保持位置，不用整页旧高度反复补偿。只有明确滚轮、触摸、键盘或滚动条操作才接管自动定位；布局变化本身不算用户滚动。切换会话/来源或发起新定位后，旧的异步返回不会再把页面拉回旧位置；同文件审阅、侧栏和文件列表刷新保留阅读状态。

轮次完成后过程章节默认收起，同时保留底部跟随或当前阅读锚点，不把主要报告推走；读者的手动展开选择仍优先。

运行状态优先位于用户消息下方的助手原位标题。只有它滚出视口（例如长回复把标题推到上方）时，输入区上方才出现同宽的浮动状态行，提供当前状态/步骤、用时及返回最新等入口；原位标题仍可见时不重复显示。浮动行覆盖输入区上方，底部预留保持恒定，不移动输入框、不缩放或重排对话区域；120ms 淡入淡出，系统减少动态效果时为 80ms 透明度过渡。等待显示「等待你的选择 · 问题」且暂停时钟；服务商重试保留明确原因、次数与倒计时，常驻 polite 状态播报不变。

跟随时页面以 τ80ms 平滑滑向底部，不按整行跳动；每帧及布局后绘制前限落后 ≤64px，底部恒定预留 108px（72px + 浮动状态行 36px），显隐不改变布局。距底部 1.5px 内准确归底，单次变化超过一屏先定位到距底部 64px 再滑动；180ms 折叠动画在跟随时仍保留。任何用户滚轮、触摸、键盘或滚动输入立即中断程序运动，程序写入不当作用户滚动。

状态行、头部提示、「最新」与 minimap 最后标记共用返回规则：两屏高度内以 300ms 补间持续追向实时底部，开始即恢复跟随；更远直接跳转。历史前插锚点恢复、会话切换首屏、查找/消息定位仍立即执行；减少动态效果时立即固定到底。流式最新不重复读历史。minimap 少于三轮隐藏，标记具名可键盘访问；当前窗口最多保留 64 份阅读位置，不承诺重启恢复。

右侧 minimap 在对话处于底部或跟随状态时立即标记最新消息，回复流式增长和新增轮次时同步更新；阅读其他位置时，标记视口约 30% 高处阅读线对应的条目，而不是顶部边缘刚露出的一小段。历史分页稳定后刷新标记，避免底部仍指向较早消息或流式期间滞后。

流式答复与推理使用同一完整字形渐进节奏，不拆组合字符或代理对；每帧随积压释放，等待达到 250ms 的字形当帧释放，流结束后余量在 120ms 内排空。每字从自己的释放时刻以 220ms 透明度淡入，同时至多 128 个，不做位移、模糊或变色。代码块、行内代码、数学与表格仍渐进但不逐字淡入；历史/保存、替换文字及减少动态效果立即显示且不淡入。

流式回答中未闭合的强调、行内代码和链接不再露出语法标记。

模型选择按服务商分组，可搜索并显示上下文容量；模型与思考选择立即更新标签并关闭菜单，在后台提交，失败回滚并在输入框内显示错误，不锁住整段输入，也不触发整段会话/历史刷新或占用探测。思考入口区分关闭、不支持和具体等级；主进程以**当前运行时公布的等级**校验，随模型切换更新，而不是固定 off…xhigh 清单。原生提供时可用 max/inherit，均有中英文标签；未连接不误报为不支持思考，不允许修改时不授予操作。`@` 文件菜单仍支持目录钻取与面包屑，附件 chip 保留类型、大小、尺寸及拒绝原因；启动与输入错误本地化并保留技术详情。

输入占位提示为「输入消息，/ 调用命令，@ 引用文件」，输入和按钮保留独立焦点提示。检查准入期间按 Enter 可进入待发送，检查完成且允许后仅提交一次；确定不允许或仍未知时保留输入与原因。外部占用、归档及旧节点使用对应只读操作，待发送不授予写入权限。

消息、历史/审阅搜索、命令面板与设置文本字段使用单一输入表面：复合输入的内层保持透明，不叠加黑色背景或方形焦点阴影；键盘焦点仍由外层或独立输入的可见轮廓提示。文本外观修正不移除按钮、选择框或其他原生控件的操作与焦点提示。

对话正文宽度拖柄支持拖动、方向键及 Home/双击恢复 760px，偏好接受 360–1600 的有限数值。头部为「项目 / 会话标题」：项目弱化且可点击，标题单行并有完整提示，双击重命名，草稿为「新建会话」。至多一个可点击状态提示：「运行中」返回最新，「等待你的选择」聚焦问题，终端占用显示只读提示。右侧只有已保存文件才显示「会话历史与分支」，另有收件箱与面板开关；28px 控件共用中心线，未读徽标使用深色文字（对比度至少 6.9:1）。工作面板默认 420px、常规上限窗口 40%，阅读区预留 560px；空间不足先让出面板宽度，仅自动收起的侧栏随空间恢复还原。

窄窗口收起侧栏后，它不再占用工作面板宽度；1100px 窗口可容纳 420px 工作面板。

macOS hiddenInset 窗口在侧栏收起后仍预留 88px 红绿灯区，避免与按钮/标题重叠；进入原生全屏后取消预留。侧栏收起和展开为一次连续位移，头部与正文同步移动，并遵循系统「减少动态效果」。

共享动效为状态切换 120ms、折叠/浮层 180ms（透明度 + 0.98 缩放）、面板/首次发送输入框 240ms、大表面 320ms。系统减少动态效果时没有空间运动，仅保留 80ms 透明度交叉淡入，关闭流式字形动画；导航不会触发输入框滑移，历史加载与前插不动画。字阶为 11/12/13/14/15/17/20/24/28px，字重 400/500/600，图标 12/14/16/20px、描边 1.75，点击高度至少 28px。

进入设置后，键盘焦点移到“返回应用”；返回时优先恢复到打开设置的控件，原控件不可用时回到输入区。重新展开侧栏后，标题栏中的侧栏按钮将焦点交给侧栏内对应按钮；隐藏但保留的页面和按钮不参与键盘导航。

日常键盘路径不设焦点陷阱；菜单、命令面板、查找与对话框按 Esc 返回原焦点，重命名/删除返回会话行触发按钮，项目悬停操作也在键盘聚焦时可见。常驻礼貌播报区域只播报状态变化，不逐 token 或逐段工具参数播报。

## 4. 配置、认证与数据所有权

| 数据 | 权威所有者 | 桌面行为 |
| --- | --- | --- |
| 当前模型、思考级别、运行状态 | 当前 omp 会话 | 原生 RPC 读取/操作；不等于全局默认值 |
| Agent 全局设置 | omp config CLI | 列举、修改单项、重置后重新读取有效值 |
| 项目配置、环境变量、配置覆盖 | omp | 按实际工作区/profile/环境解析，不建立第二套合并器 |
| 认证、OAuth、服务商密钥 | omp 原生存储与环境 | 不复制认证数据库，不把凭据值当普通设置传给渲染器 |
| 会话正文与 artifact/blob | omp 原生文件存储 | 历史按分支只读分页/跟随；明确续写后的执行上下文仍由原生恢复 |
| 字体、布局、侧栏隐藏项目与项目折叠、消息详情、耗时格式、最近工作区、通知、首选编辑器 | 桌面 | Electron `userData` 下独立偏好，不写进 omp 终端设置；不再包含主题/动效选择 |

侧栏隐藏项目与各项目的折叠状态保存在桌面偏好中，随启动数据提供并异步保存，最多保留 200 个规范化项目路径；不再由渲染器 localStorage 持久化。已有 localStorage 值在首屏绘制后迁移一次，随后删除旧键，不在启动时同步读取侧栏状态。

### 设置：常用项、高级项与外观

桌面不再提供主题或动效选择。读取旧桌面偏好时，仅丢弃退役的 `theme` 与 `motionMode`，其余偏好继续严格校验并保留；返回值和新保存文件不含这两个键，公开偏好更新接口也拒绝它们。格式错误的 JSON、其他未知键或无效值仍报错，不会借迁移重置其他偏好。此变更不修改终端 omp 的主题、原生配置、认证或历史。系统“减少动态效果”仍受支持，状态与操作不依赖运动提示。

先检查运行文件、工作区/profile、服务商/模型与思考级别。原生审批或工具相关选项以已安装 omp 导出的实际设置为准：桌面不叠加自己的 allowlist、信任规则或自动批准策略。需要回答的原生 select/confirm/input/editor 请求应由用户明确选择、输入或取消。

设置侧栏分为「桌面端」（外观与输入、通知与在场、本地运行时）、「omp」（模型与默认值、提供商与凭据、高级设置）和「关于」。高级项按 16 个中文类别组织，122 个标题经过整理；原始 key 作为次要等宽文字，原生说明标为「omp 原文说明」，搜索结果同样标明来源。模型角色从实时目录按服务商分组搜索；服务商可搜索并分为「已配置 / 登录订阅 / API 密钥 / 本地」，不展示秘密。未知结构才用 JSON，不伪造原生 schema；「仅显示已修改」只覆盖本次设置会话。

逐行双语搜索保留面包屑、命中高亮与深链。外观提供预览、尺寸与字体选择，窄于 720px 降为单列；通知和首选编辑器均为桌面偏好。关于显示桌面/omp/在场扩展/引擎版本，提供「打开日志文件夹」与不含环境变量或凭据的「复制诊断信息」。在场轮询仅在「通知与在场」可见时进行。

新增两项独立桌面偏好：

- **消息详情：**「始终显示」（默认）或「悬停显示」，仅控制轮次结束后的答复页脚；运行中不显示，没有元数据的轮次不显示空页脚。
- **耗时格式：**「进位单位」（默认）或「分:秒」。进位单位从月/周/天/时/分/秒取最高两级，如「2小时27分钟」「3天4小时」，1 小时以上不显示秒；分:秒可显示为「147:39」，不会在 60 分钟归零。时间线、停止时间、工具、子代理、收件箱与状态统一使用所选格式。

已有本应用拥有的运行时时，可明确检查原生登录服务商，再选择服务商登录并刷新模型目录；凭据存在不等于账号可用，登录能力也不保证所有 RPC 交互兼容。无运行时可启动时，「提供商与凭据」与首页使用同一恢复卡：「在终端中登录」打开同 profile 的 `omp login`，登录后重新检查；仍可手动回到终端 `/login`。桌面不建立秘密存储、不静默登录，商业 OAuth 的验证范围单列于验收记录。

重要原生项包括 `modelRoles`、`modelRoleStorage`、`defaultThinkingLevel`、`tools.approvalMode` 和 `compaction.enabled/thresholdPercent/thresholdTokens`；是否出现以当前 omp 的真实 metadata 为准。枚举字段由原生校验，不虚构下拉选项。修改可执行文件/profile 前须先断开现有运行时；新选择影响后续进程与读取范围，不把已经运行的会话迁移到另一个配置。

**原生配置写入是共享的全局修改，会影响终端 omp。** 即使在某个项目中打开设置，`config set/reset` 也不是项目局部编辑。环境变量、运行时值、配置 overlay 或项目配置可能覆盖全局值；写入成功不代表当前有效值已改变。重置表示删除全局键，不保证恢复到内置默认值；它可能露出项目或环境中的值。原生配置列表没有来源/默认值元数据，界面只在写入回执已知时显示来源，未知保持未知，不把“仅显示已修改”外推为完整配置审计。某些设置的消费者需要新会话或重启才重新初始化。

终端排查可使用以下命令；**这些命令不是无副作用的文件查看器**，omp 的初始化可能迁移自身配置、创建元数据或打开原生数据库：

```sh
omp config path
omp config list --json
# 命名 profile：
omp --profile work config path
omp --profile work config list --json
```

不要批量执行 `config get` 导出所有值或分享完整输出：显式 get 和 set 的输出可能包含秘密。不要把界面的脱敏标记写回真实配置。

### 路径与环境

通常默认配置在 `~/.omp/agent`，文件会话在 `~/.omp/agent/sessions`，但这不是所有安装的固定路径。`OMP_PROFILE`（以及兼容变量 `PI_PROFILE`）、`PI_CONFIG_DIR`、默认 profile 的 `PI_CODING_AGENT_DIR`、原生 `.env` 与符合原生条件的 XDG data/state/cache 根目录都会影响实际位置。命名 profile 有独立原生根目录；桌面基础配色和偏好迁移不改变 profile。

应在桌面与终端使用一致的工作区、profile 和环境。不要仅凭目录名反推出历史项目路径；会话头部的 `cwd` 才是原生记录。存在的工作区和会话文件按真实路径统一身份，避免 `/var` 与 `/private/var`、符号链接或登记路径别名重复分组/打开；不可用工作区保留原路径，不凭空授予访问。读取偏好时的归一化不是改写原生会话头。不要复制实际认证或历史到测试目录来制造验收数据。

## 5. 历史与搜索边界

侧栏索引原生普通 JSONL、gzip 归档及已登记的外部会话路径；逐来源错误/上限诊断与可用结果同时保留。标题、工作目录与首条用户消息预览采用有限读取；**侧栏搜索不是所有历史正文全文搜索**。嵌套 subagent transcript 从父任务查看，不作为独立主会话混入列表。

### 查找与历史搜索

Cmd/Ctrl+F 同步打开并聚焦查找框，紧接着键入的文字进入查询，不会落入聊天输入区。索引与匹配分块处理当前已加载对话，包含思考、工具摘要/字面输出和子代理名；命中展开折叠并定位高亮，提供准确数量与前后导航，minimap 标出位置。语法高亮由模块 worker 执行，不在揭示内容时阻塞主线程。「搜索全部历史」转命令面板，不将已加载窗口冒充全来源。

查找栏开启期间，向上加载更早历史会暂停，避免命中位置随分页变化；关闭查找栏后恢复加载。需要检索更深范围时仍可用「搜索全部历史」，当前查找只覆盖已加载对话。

命令面板消息检索在授权 JSONL/gzip 中包含用户/助手正文和工具参数/结果，不含附件、sidecar 或思考。默认最多 50 条、上限 100 条，预算 1.5 秒、最多 1,000 来源、每文件解压后 8 MiB；触及限制显示部分覆盖条幅及「在当前会话中完整搜索」，新查询取消旧查询。同会话相同片段合并成一行「N 处」，不同会话不合并，结果显示工具名（如「task 结果」）和紧凑时间；打开定位准确分支/entry，不恢复运行时、不调用模型，也不涵盖未落盘 token。

「会话历史与分支」按轮次树、分支线与节点标记组织记录，技术事件默认隐藏。动作明确写为「从最新内容派生新会话」，仅原生支持时才提供「从所选消息前派生」；查看节点本身不执行分支写入，不把选择自动等同于派生起点。

### 历史来源边界

无法读取的历史来源集中为侧栏底部简短计数与「查看」，如「1 个会话无法读取 · 查看」。展开后可查看原因与重试，完整路径留在详情中，不挤占会话导航。历史/来源错误限定当前视图，导航后清除；保留大会话阅读窗口再切换来源不应误报新会话「来源不可用」。

- 自定义 `--session-dir` 或未登记外部位置不保证自动发现；使用明确的会话文件选择入口。
- SDK 注入的 SQL/Redis 等替代存储不在本桌面的本地 JSONL 历史索引范围内。
- 未发送的新建草稿不创建原生条目或文件；以前遗留的空白已保存会话与派生目标仍是持久来源，缺失时不可冒充未保存。根据真实来源状态丢弃或移到废纸篓。
- 列表预览不是模型上下文重放；只读正文按已保存分支显示，可保留 clear/压缩前的历史并标记摘要。它不迁移源文件，也不推断未保存的原生内存状态。真正续写的上下文、分支执行与旧格式迁移仍由 omp 负责。
- 不手工编辑正在使用的 JSONL；不要同时从两个进程写入同一活动会话文件。
- 历史正文保留所选祖先链的压缩摘要、reset/clear 前后记录；树每页最多 1,000 节点，向上滚动接近顶部时自动补入更早条目。大于 100,000 条目的历史仍按祖先链分页，不用原始源码视图冒充完整聊天。索引使用可丢弃的临时 SQLite 元数据，不是第二套 Agent 会话权威存储。异常尾行、不可用资源及上限显示诊断；超大单条记录可分段查看来源细节。
- gzip 历史只读流式读取；移动记录中的 `previousSessionFiles` 是来源线索，不拼接成另一条消息时间线。明确从归档 fork 时先受限暂存解压内容/资源，再由真实 omp 创建新会话并核对完整性，临时目录随后清理；原压缩文件保持不变。
- 历史加载/分页失败保留已可读内容并提供明确重读入口；不会混合不同来源版本的分页。来源、分页及读取限制不是原生模型上下文限制。

## 6. 文件、附件、差异与 subagent

文件面板是工作区内的**只读浏览/预览**，不是 PI 插件文件编辑器、内嵌浏览器或任意本机文件服务。主进程检查真实路径，限制符号链接越出工作区。文本、图片存在读取大小限制；二进制或过大文件有明确不可预览状态。

### 文件对象与编辑器

工具文件对象右键提供在面板中预览、在编辑器中打开、快速查看、在访达中显示和复制路径；空格触发 macOS 快速查看，Cmd/Ctrl+Enter 在编辑器定位，拖出可交给访达/编辑器。复制路径不携带行选择器。首选编辑器支持系统默认、VS Code、Cursor、Zed，打开使用独立进程参数而非 shell；所有预览、定位、打开和拖出仍校验工作区及真实路径，拒绝越界符号链接，不把链接当作任意本机文件权限。

工作面板只有「文件 / 更改 / 任务 / 会话」四个目的地，文档标签只在对应目的地内显示，使用溢出与「+」菜单。文件支持隐藏文件、引用点与 Git 状态，临时预览标签为斜体，最大化后分栏；任务按委派分组并可过滤、查看报告。会话检查以身份、单一活动卡、上下文、生成与花费组织，思考等级本地化，策略默认收起。

工作面板标签在 420px 宽度下带三位数计数时不再重叠，徽标显示上限为 99+，更窄时仅保留图标。

从聊天中的本地文件链接打开嵌套文件后，点击“返回文件”（Back）会展开其父目录，在文件树中定位并聚焦该文件；重新打开同一文件 tab 不重置已有目录树和搜索状态。

工具文件目标的提示为“打开工作区中的当前文件”。带行号引用支持 `path:N`、`path:N-M`、`path:N+K` 与 `path#LN-LM`，打开后滚到并高亮精确范围，显示“第 N–M 行”；hashline 的 `#TAG` 不当作行号。文件代码预览保留行号，Markdown 可切换“预览/源码”；从对话打开时显示“当前工作区版本”，明确这里不是工具调用当时的历史快照。越出工作区或文件已不存在时显示原因，不放宽读取权限；5,000 行预览上限不变。

当前读取限制：UTF-8 文本 2 MiB，按签名识别的 PNG/JPEG/GIF/WebP 图片 10 MiB，代码预览最多 5,000 行。文件搜索查路径而非正文，跳过 `.git`、`node_modules`、`.venv`；最多遍历 10,000 项、返回 500 个结果，触及边界保留已有结果并显示部分结果诊断。`src/foo` 将搜索范围缩到 `src/`；空查询显示有限根文件与引导。目录树不列出符号链接。

附件经原生文件选择、拖放或明确粘贴的图片字节授权后读取。剪贴板接受经签名核对的 PNG/JPEG/GIF/WebP，单图最多 10 MiB；剪贴板来源没有磁盘路径，不伪造文件授权。普通文字粘贴保留换行，不把 HTML 当成聊天标记执行。外部附件授权不开放整个外部目录。发送前检查是否含秘密或不应外发内容；发送后的信息不能靠删除 chip 撤回。

待发送附件最多 24 个、总计 32 MiB，授权有效期 30 分钟，并限定真实工作区。保存的是授权时快照；过期显示原因并要求明确重新添加，不自动从磁盘重读。主进程只在提示词受理后消费附件 ID；发送失败保留草稿，发送期间的新编辑不应被旧请求完成时清空。fork 转移草稿/附件也不代表已发送。

### 审阅改动

**本轮审阅默认只展示每个文件的一份最终净变化，不要求 Git。** 同一文件多次修改合并成开始到结束的结果；已证明改回原样、或创建后又删除的文件不列入最终清单。答复后的「本轮改动 · N 个文件 · +A −R」与「审阅全部改动」使用同一结果，点击文件打开其最终 diff，不再默认按 1/N 逐步浏览或累加每次修改的行数。活动轮次和尚无结果的加载阶段不显示最终改动卡；无法确定时在审阅中保留已知文件并说明原因，不把未知显示为零，也不以「0 个文件」加部分覆盖提示替代完整历史收集。

增删汇总只计能够确定的最终行数；缺少完整内容时显示内容缺口或二进制说明，不用零或 Git HEAD 的行数冒充本轮结果。**文件确实发生变化、完整内容是否可用、修改来自谁是不同问题。** 前后哈希可以证明区间内有变化，即使正文已释放或工具未留下 diff，文件仍保留；只有命令目标或报告中的文件名不能证明修改。并发用户或其他会话修改可能落入同一区间，不能仅凭哈希归给某个代理。

「过程与来源」默认收起，需要时再查看中间操作、命令、记录 diff 和来源入口；主/子代理的已授权原生工具记录始终参与最终结果，不仅在快照失败时才使用。子证据沿真实父子授权收集，迟到结果按原始调用核对；不按代理名称或报告正文猜来源。可选过程明细最多保留 256 步 / 1 MiB，省略会明确标记；该展示限制不停止后续证据处理，也不降低最终净结果的完整性。文件对象仍支持编辑器、快速查看和拖出，删除文件不提供不存在的当前文件入口；从文件链接打开的仍是「当前工作区版本」，不是历史端点。

子代理之间的原生协调消息不会仅因以 user 角色保存就切断委派；必须有明确的代理 steering 元数据，续写还需满足同一已授权子代理与所选父轮次的归属证据。新的普通用户任务仍是边界，不把后来无关任务的文件并入旧答复。离屏轮次不提前占满证据读取队列；进入视口后按需查询，同一来源的历史或子记录更新会重新读取，而不是一直沿用旧的合并结果。

桌面自有会话仅在实际发送前捕获基线，等原生会话及仍活动的异步/子任务收敛后观察终点；仅出现答复或主代理结束不算全部完成。运行中插入消息不会重新捕获一个中途基线并冒充整轮；中断、身份变化、扫描不完整与共享区间保留限制说明。

捕获采用内存中的哈希清单与有界文本，按机器总内存和可用内存动态调整全局预算，多个会话共用；压力下先释放文本、保留已记录哈希。应用不写磁盘快照、不做溢写或永久中间版本缓存，但不承诺操作系统零 swap。当前每次扫描默认 30 秒、最多 100,000 个条目、64 层；单文件文本保留上限 2 MiB，超出仍可流式哈希。跳过版本控制、依赖、构建与缓存目录及符号链接，不保证全项目覆盖；这些工作区扫描边界不是历史收集的累计上限，详见 [架构说明](ARCHITECTURE.md#本轮最终改动捕获与证据)。

最多保留 24 份捕获记录，最终计算后释放端点正文，最终 diff 也可能因内存压力被释放。主进程重启会丢失这些内存端点；旧轮次、外部终端轮次及已淘汰记录从完整原始历史分段读取所选轮次的工具证据，逐项归约最终净结果，而不是累计保留整轮正文或操作数组。不会因历史累计页数、消息数、字节数、来源数、深度或操作数达到旧上限而停止收集；超大原始记录同样分块投影。载荷仅在 RAM 中处理，不新增正文磁盘缓存；已有可丢弃的偏移/身份元数据索引不变。

原始证据确实缺失、损坏、身份不确定或单个 patch/diff 超出运算能力时仍需说明具体原因；完整历史较长本身不是缺失理由。不能拿今天的文件内容冒充历史终点，也不能补造未知内容；分段收集不承诺任意大小最终补丁都能精确重建。在 2026-10-01 的历史验证中，用户报告的原会话固定最终答复通过了只读冻结父/子历史的实际模块 smoke：15 个文件、完整且不再 pending，包含最后文档端点。当时重建后的 Electron 与目录包均实际显示该轮 15 文件、+35/−7「仅统计精确行数」，并打开 `contracts.ts` 的原生精确 diff，无收集中、部分覆盖提示或警报；这仍不等于全部文件都有精确 diff/行数，内容未知者仍保留说明，也不证明 v1.0.0 DMG 重放过该场景。此前一文件 +1/−1 的原生编辑、冷重启、旧包与无改动答复观察仍仅证明当时场景；超长正文 fixture 的界面限制也不是此次缺文件或空白原因的证明。详见 [原会话回归的历史验收](VERIFICATION.md#当前验收原会话最终答复缺文件回归--2026-10-01)。

**当前 Git 工作区审阅是单独标注的视图，不是本轮最终结果。** 它可能包含用户或其他进程的修改，区分 staged/unstaged，先加载元数据、选择文件时再读取补丁。根目录不必是仓库：按引用文件发现嵌套仓库（最多 500 个引用、32 个仓库，缓存 30 秒）；无 Git 的当前工作区视图有明确说明，不影响本轮审阅。未跟踪文本按实际内容显示全新增 diff 与新文件标记，支持 UTF-8、空文件、BOM、CRLF 和无末尾换行，受 4 MiB / 5,000 行限制；二进制或超限不伪造 patch。只读查询不启用 external diff/textconv，命令输出与补丁读取仍有大小限制。

Changes 工作台保留模糊筛选、文件列表和单个聚焦 diff；列表先显示文件名，目录弱化并居中省略。≥900px 或最大化时支持并排布局，差异内有词级高亮、上下文展开、文件头操作及新旧行号；J/K 切文件、N/P 切 hunk、W 切换换行、U/S 切布局。无工作区、无差异及筛选无结果分别说明；所有审阅均为只读，不提供暂存、撤销或快照回滚。

### 内联委派与子代理详情

- 每次 task 的名册汇总与行来自同一对账证据，提供「查看原始参数」。实时运行 task 的声明名额未关联子代理前为中性「等待中」，头部也计为等待中；未观测的保存调用仍为「状态未知 · 尚未关联」，已结束调用未启动的名额保留已停止/失败，不冒充真实任务。
- 名册按真实祖先关系缩进，保留连接线、分支折叠与子任务计数；每行显示名字、任务、当前步骤以及「状态 · 耗时」，同级顺序不因选中或状态变化重排。参数与技术详情不占据正面，零值/未知指标不补造。
- 点击打开只读子面板并同步选中；未锚定任务与任务总览复用名册行，可证明的异步结果归回原调用，无法关联的说明原因，不按位置或点号名称猜关系。
- 子面板依次为祖先面包屑、状态与耗时、一行「模型 · 步骤 · 子代理累计 tokens · 费用」、一处「任务说明」折叠、过程与一份报告。token 口径与页脚一致，名称/金额使用共享格式，不再重复分配气泡或结论报告。保留定位、刷新与按需来源详情。
- 状态综合 task、进度、交付、wait/jobs/cancel、复活代次与授权子记录；同一代已确认终态不被稍后模糊证据降级。终端同步任务按声明 ID、父会话头和时间唯一关联，歧义留在未分配名单。
- 未参与扩展时仍区分推断运行与未知；参与进程以锁/socket 为准。已处置的后续消息保留完成事实，中途工具失败不直接变成最终失败，问题数排除已恢复操作、预期失败、用户停止与已完成报告。

终态 yield 文本与结构化有效字段保留为可见报告，不把 JSON、身份回显或 false 标志当结论；运行中不提前制造报告。重读期间保留子会话身份，诊断按需展开，完整原始来源仍经授权访问。

Subagent 由 omp 创建和调度。活动详情通过本应用拥有的 runtime 与原生 child 身份授权，读取**持久化、按所选分支分页的历史**，并叠加真实事件形成的有界实时消息序列，不是只显示最后一条实时消息。跟随父会话最新内容时，正常落盘推进不会清空或排除已验证的子会话流式消息；明确选择历史分支、翻阅子会话旧页、使用保存模式或失去观测时则不叠加实时行，不将新内容混入旧页。序列与落盘页按受会话约束的原生身份/元数据对账，不按相同正文合并；缺少身份或触及保留上限有不确定/截断提示，已保存历史仍通过分页访问。保存子会话按父会话、具体 tool call 与祖先链只读发现，不为查看重启 RPC 或任务。

任务说明只来自真实分配消息或上下文，在子面板集中为一个折叠，不因历史页缺少用户行而重复制造提问。真实多层及多父关系保留；仍被观测的子任务打开后代优先使用实时身份，保存恢复绑定父来源/分支/版本。失去观测不继续冒充活动，有独立权威观测的后台任务不因主代理结束而被终止；缺失/歧义不改名为成功。

子会话详情与主对话相同：向上滚动自动补入更早消息直到开头，新消息继续追加在下方，压缩摘要不阻断向上阅读。分页和折叠按子会话消息锚点保留阅读位置，不把摘要之前的内容当作重新加入模型上下文。切换来源、分支或重读后，迟到的异步正文、导航与资源上下文不得覆盖当前选择；来源版本不一致时不混页，保留可读内容并提示重读。页面游标由界面管理，无需输入或编辑。子任务与资源入口仍需主进程按父来源/祖先链或 owned runtime + child 身份授权，不因在总览可见就开放任意文件。

子代理状态需结合完整证据判断，不把单个中断/取消通知直接当作最终失败，也不把未知或陈旧记录改成成功。各状态的实际窗口证据见 [VERIFICATION.md](VERIFICATION.md)。

保存输出/恢复区域在工作面板独立资源 tab 中只读分页，每页 64 KiB，提供加载、失败重试和前后页；按父来源及不透明引用定位，保留页游标与阅读位置。文本使用代码/原文呈现，不通过 Markdown 触发外部资源加载；支持的栅格图片可预览，二进制/缺失资源明确标记。原生文件引用中的图片（`fileMention.files[].image`）也纳入保存图片的有界读取，可经授权来源恢复完整图片；图片路径本身不授予文件访问权。历史内联图片与按需打开都受来源授权和字节上限约束，损坏或缺失图片不会隐藏可见正文，也不被替换图冒充成功。子任务发现和资源扫描有限额，可能只列出部分旧任务，必须结合诊断理解。

## 7. 原生 RPC UI 的明确限制

支持的是原生 RPC 表达的标准选择、确认、单行输入、编辑请求、通知、状态与文本 widget。原生扩展的任意 TUI 组件、自定义 header/footer/editor 工厂、终端输入钩子、自动补全提供者组合和 TUI 主题控制不能直接转成桌面组件。遇到仅终端支持的扩展界面，应在终端 omp 使用；桌面不能静默批准或用成功占位代替它。

当前会话的原生 ask 在对话内显示，必答问题不被 Esc 关闭；启动和其他会话请求仍走模态路径并保留真实归属。原生截止时间使用本地化相对倒计时，未给超时不虚构期限；运行时 store 统一处理过期，不因重挂载延长期限或重复回答。等待期间输入框保留草稿且可编辑，发送禁用并说明原因，已结束提问留下本地化回执。

**omp 18.3.2 的启动扩展限制：** 在 `session_start` 中同步等待 UI 回答可能因原生启动分发顺序阻塞而在 30 秒后超时，即使匹配的回答已经写入 stdin。独立、不经过桌面的诊断已复现；桌面不修改原生代码、注入批准或伪造成功来绕过。正常运行会话中的 ask/select 已实测通过，这不是所有原生对话框的共同限制；详细时间证据见 [VERIFICATION.md](VERIFICATION.md)。

原生 RPC 没有通用 `list_sessions`、文件补全或全量设置 CRUD/schema 接口。桌面的历史索引、工作区补全与 config CLI 适配是明确的本机展示边界，不应被理解为另一个 Agent 内核。

传输同样有明确界限：物理帧 1 MiB、v2 重组帧 64 MiB，初始化消息总量 128 MiB；超限会报错，不会把截断结果当成完整历史。原生请求/模型/OAuth 不设桌面强制完成期限或自动重试；发现可执行文件的探测和退出时清理则有界。

## 8. 安全与故障处理

通知、失败轮次卡与内联提示使用同一错误呈现：先说明本地化的「发生了什么」，只在原因已知时给具体建议。只有确实来自 omp 的错误才显示「omp：原文」；未知桌面错误只显示上下文中文标题，原文留在「技术详情」，不误标为 omp 错误。IPC 前缀不展示，不同故障不合并成泛化错误。运行时崩溃只有一条可「重新连接」的通知并保留草稿；历史/来源错误限定当前视图，导航后清除，自动后台刷新失败只保留局部诊断。

- 渲染器不直接获得 Node、原始 IPC 或任意命令执行接口；外链经过主进程协议检查。不要通过关闭 Electron sandbox 来解决环境问题。
- **渲染器沙箱不是 Agent 工具沙箱。** omp 及其原生扩展以当前用户权限执行工具，可能修改工作区、运行命令或访问网络。只打开可信项目，按原生能力配置权限并审阅交互。
- 本地桌面不等于模型离线：服务商请求、原生工具和扩展可能联网并产生费用。
- Markdown 的 HTTP(S) 图片可内联加载，会向远端服务器发出请求；使用 no-referrer 不等于匿名或离线。HTTP(S) 音频/视频提供内联播放控件，采用 `preload=none`，并校验 URL、拒绝 URL 内嵌凭据、清理嵌套 source；播放失败后才提供外部打开入口。这不等于提供 PI 插件浏览器。
- 找不到运行时：检查安装、可执行文件路径与 GUI 环境；不要指定一个仅名字类似 omp 的任意程序。
- 无模型/认证失败：用同一 profile 在终端完成真实配置，确认服务商可用后重新建立会话。
- 设置保存后未变化：检查覆盖来源和当前工作区/profile；不要反复覆盖整个配置文件。
- 历史为空：核对 profile、原生实际根目录、自定义会话位置与是否已落盘，不要将空列表直接解读为数据丢失。
- 停止/退出异常：保留脱敏错误与时间，区分原生错误、传输错误和窗口状态；桌面不自动重发用户请求。
