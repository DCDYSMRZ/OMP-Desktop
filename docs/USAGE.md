# OMP-Desktop 使用说明

## 1. 桌面与运行时

OMP-Desktop 是已安装 **omp** 的 Electron 前端，不包含 Agent 内核。主进程直接启动本机可执行文件，以 `omp --mode rpc-ui` 的原生 JSONL 协议通讯；不是 PI runtime、远程服务或第二套工具执行器。

模型请求、工具、MCP、Skills、扩展、subagent、认证和会话持久化属于 omp。窗口、主题、字体、布局、文件预览与受限 IPC 属于桌面。桌面不提供 PI 插件市场、计划任务、PR 工作流、远程主机、云同步、独立提示词增强或自定义权限注入。保留的原生 omp 扩展能力与被移除的 PI 桌面插件系统不是同一件事。

当前协议适配基于 omp 18.3.2 的接口。版本号相近不代表协议兼容；安装与窗口实测状态见 [VERIFICATION.md](VERIFICATION.md)，不能把本文操作说明当作已通过验收的证据。

## 2. 安装 omp 与首次配置

已有 omp 时无需再次安装。先在普通终端确认：

```sh
omp --version
```

未安装时，按 [oh-my-pi 官方安装说明](https://github.com/can1357/oh-my-pi#install) 选择安装方式。macOS 可用：

```sh
brew install can1357/tap/omp
```

或者在已经安装符合上游要求的 Bun 后：

```sh
bun install -g @oh-my-pi/pi-coding-agent
```

安装 omp 与安装本项目的 Node 依赖是两件事。桌面不会自动下载另一个 Agent，也不会把 `pi` 当成备用运行时。

**首次没有可用模型时，先在终端配置 omp。** 原生非交互 `rpc-ui` 在无法解析模型时会在发送 ready 之前退出，因此不能依赖桌面内部 RPC 登录完成所有首次配置。可以运行：

```sh
omp setup
omp
```

按原生向导选择真实可用的服务商、认证方式与默认模型；在原生会话中按需使用 `/login`、`/model`。API 密钥、OAuth 与自建服务商配置遵循 omp 自身说明，不要把密钥粘贴到桌面普通设置、诊断日志或聊天中。本地无认证模型是合法配置，但必须确实可以使用；不要填写虚构模型或占位密钥以绕过启动。某些 OAuth 服务商需要终端交互或秘密输入，也应在原生终端完成登录。

如果使用命名 profile，首次配置和桌面必须指向同一个 profile，例如：

```sh
omp --profile work setup
omp --profile work
```

桌面设置中的可执行文件应指向实际 `omp` 文件，不是 shell 命令、附加启动参数或 PI 可执行文件。Finder/Dock 启动的环境可能与终端不同；遇到找不到 omp 或工具链的问题，核对该路径、profile 以及启动环境，而不是重新创建一套凭据。

运行时发现会尝试恢复 login-shell 的 **PATH**，以找到本机 omp 与工具链；这不等于继承另一个终端中临时 `export` 的任意变量。Finder/Dock 无法自动获得该终端的临时 API key/代理/自定义服务商变量。使用原生认证、相同 profile 与原生 `.env`，或从需要的环境直接启动应用可执行文件；不要把 PATH 恢复误解成秘密变量同步。

## 3. 工作区与会话

1. 选择本地项目目录作为工作区。它决定子进程 `cwd`、项目级配置解析与文件面板边界。
2. 新建会话，或从原生历史列表**只读打开**已有会话。历史中未索引的 JSONL 可通过原生文件选择入口打开；按界面要求选择所属工作区。打开文件不是恢复执行，不会为查看而启动会话、改写原 JSONL 或请求模型。
3. 新会话中发送消息；历史会话则先区分下述查看、续写与 fork。可用的模型与思考级别由原生公布；列表存在不保证每个模型的凭据都有效。
4. 正在运行时，steer 表示引导当前执行，follow-up 表示排队后续输入；它们使用 omp 的原生队列，不是桌面自行串行重试。
5. 停止按钮发送原生 abort。不要把停止等同于撤销已执行的文件写入、命令或外部请求。退出窗口会关闭本应用拥有的 omp 子进程，不应终止用户另开的终端 omp。

消息被受理、单次回复结束、全部后台任务结束是不同状态。命令 ACK 或 `agent_end` 不是会话完全静止的证据；原生 `session_settled` / `isSettled` 才描述完整收敛。断线、进程退出或错误后，不应假设最后一条消息未被处理，也不要无判断地重复发送有副作用的请求。

### 只读查看、续写与 fork

- **查看：** 侧栏打开的是已保存的原生记录投影。会话树在现有会话菜单中打开，节点只切换查看分支，不改写原生叶节点、不执行 branch 或 fork；回到“跟随最新”后读取最新落盘分支。没有独立的历史状态/Continue 顶栏。
- **发送与阻塞原因：** 可发送时直接点击 Send；对于可恢复的历史，这是明确以原生 `--resume` 续写同一个 session ID/文件，不需另点 Continue，也没有常驻绿灯。阻塞时 Send 旁直接显示原因文字，点击可打开完整说明并刷新状态。观察结果不是独占锁或永久可写保证，主进程仍在实际写入前检查。
- **终端占用：** 外部 omp 即使停在输入提示符、没有生成 token，也仍拥有该会话。桌面可编辑并保留草稿，但不能向原会话发送、向终端注入消息、终止它或强占文件。跟随只反映完整持久化记录，不是终端屏幕镜像或未落盘 token 流。正常退出后重新观察为空闲，才允许明确发送续写。
- **明确 fork：** 打开发送旁的阻塞说明，在确有可读持久来源时选择 fork 并确认创建原生新分支；会话菜单也提供明确的来源操作。确认说明共享工作区，成功后把当前草稿文字、文件引用和附件移到新会话，**不自动发送**；失败保留原草稿。尚未落盘、没有可读来源的新会话不提供虚假的 fork 恢复。原生 `--fork` 创建不同 session ID/parentSession，不改写源会话；从保存的最新分支开始，**不是从任意选中的树节点 fork**。两个会话仍共享工作区文件。
- **只读来源与未知状态：** 归档或指定树节点不是原文件续写位置；需要原位置续写时返回可恢复来源的“跟随最新”。探测失败或相关证据有歧义时禁止原会话写入。Darwin 占用检查不是全客户端原子租约；新建/fork 的 owned 身份由主进程校验，不因无关 profile 的缺失 breadcrumb 一概阻塞，但同一目标证据仍阻止写入，恢复既有来源仍保守检查。

改名与已接管会话的原生 branch 是明确的写操作，和只读树浏览分开。clear/压缩前的已保存正文仍可查看，但可见历史不等于全部内容再次发送给模型。桌面不提供 PI 快照回滚、任意历史删除或归档管理；只读归档支持不等于替原生管理归档生命周期。

### 消息呈现、导航与输入

思考、普通工具和中间片段以紧凑行/“过程”折叠呈现，最终正文单独显示；点击展开原生细节，正常完成的工具不重复显示成功徽标。`task` 委派卡留在调用位置，不随过程一起隐藏。用量/价格来自原生记录，答复下方摘要标为**最近一次请求**，展开后逐请求展示；不是整轮或整个会话累计，也不是商业账单保证。每条答复下方提供“复制答复”，不再提供整段对话复制。

对话右侧 minimap 用刻度定位各轮；悬停或键盘聚焦可预览，预览优先取最终答复并简化 Markdown，点击跳转。离开底部后停止自动跟随，回到底部再继续跟随。当前窗口内切换会话会恢复阅读位置与跟随状态，最多保留 64 个会话；这不是重启后持久化的阅读记录。已向前翻页的历史先恢复包含原锚点的页面，再定位正文；读取失败或版本变化不抹掉位置，只有一致历史确认锚点已消失才回到最新。流式答复逐步显示，结束或系统开启“减少动态效果”时立即显示全文。

输入区用同一个“模型 · 思考级别”入口打开选择器：模型可搜索并显示服务商，当前模型/级别带勾选；可选项由原生提供，不是桌面另设默认值。未连接或不允许修改时入口不可用，选择成功后以原生读回为准。

对话正文两侧的宽度拖柄支持拖动、左右方向键微调，以及 Home/双击恢复 760px。宽度作为桌面偏好保留，重载后恢复；主进程只接受 360–1600 的有限数值。标题栏的工作目录标签显示文件夹名称，悬停可查看完整路径；点击“切换工作目录”会打开目录选择器并启动所选工作区，不是仅在文件管理器中显示目录。窄窗口重新展开侧栏时，工作面板先让出宽度；仅由布局自动收起的侧栏会在面板关闭后恢复。侧栏与面板退出保留收起动画，系统减少动态效果开启时立即完成。

进入设置后，键盘焦点移到“返回应用”；返回时优先恢复到打开设置的控件，原控件不可用时回到输入区。重新展开侧栏后，标题栏中的侧栏按钮将焦点交给侧栏内对应按钮；隐藏但保留的页面和按钮不参与键盘导航。

## 4. 配置、认证与数据所有权

| 数据 | 权威所有者 | 桌面行为 |
| --- | --- | --- |
| 当前模型、思考级别、运行状态 | 当前 omp 会话 | 原生 RPC 读取/操作；不等于全局默认值 |
| Agent 全局设置 | omp config CLI | 列举、修改单项、重置后重新读取有效值 |
| 项目配置、环境变量、配置覆盖 | omp | 按实际工作区/profile/环境解析，不建立第二套合并器 |
| 认证、OAuth、服务商密钥 | omp 原生存储与环境 | 不复制认证数据库，不把凭据值当普通设置传给渲染器 |
| 会话正文与 artifact/blob | omp 原生文件存储 | 历史按分支只读分页/跟随；明确续写后的执行上下文仍由原生恢复 |
| 主题、字体、布局、最近工作区等 | 桌面 | Electron `userData` 下独立偏好，不写进 omp 终端设置 |

### 常用与高级设置

先检查运行文件、工作区/profile、服务商/模型与思考级别。原生审批或工具相关选项以已安装 omp 导出的实际设置为准：桌面不叠加自己的 allowlist、信任规则或自动批准策略。需要回答的原生 select/confirm/input/editor 请求应由用户明确选择、输入或取消。

低频原生选项按类别折叠；搜索用于定位实际配置项。不为每个原生设置重复设计专用业务表单，也不把 CLI 未导出的枚举/依赖关系伪装成完整 schema。未展示的键保留不变。凭据只显示配置状态，并引导回原生认证入口。

已有本应用拥有的运行时，才可明确“检查原生登录服务商”，再对选定服务商执行 Sign in，转交原生 login；登录后重新读取服务商信息和模型目录。原生报告存在认证信息不等于账号已验证，报告登录能力不保证每个服务商都支持 RPC 交互。未连接、原生拒绝或仅终端支持时仍回到 `omp` 的 `/login`；桌面不建立秘密存储，也不静默探测/登录。真实商业服务商 OAuth 的验证状态单列于验收记录。

重要原生项包括 `modelRoles`、`modelRoleStorage`、`defaultThinkingLevel`、`tools.approvalMode` 和 `compaction.enabled/thresholdPercent/thresholdTokens`；是否出现以当前 omp 的真实 metadata 为准。枚举字段由原生校验，不虚构下拉选项。修改可执行文件/profile 前须先断开现有运行时；新选择影响后续进程与读取范围，不把已经运行的会话迁移到另一个配置。

**原生配置写入是共享的全局修改，会影响终端 omp。** 即使在某个项目中打开设置，`config set/reset` 也不是项目局部编辑。环境变量、运行时值、配置 overlay 或项目配置可能覆盖全局值；写入成功不代表当前有效值已改变。重置表示删除全局键，不保证恢复到内置默认值；它可能露出项目或环境中的值。界面读回有效值，并在原生命令提供时显示覆盖来源；reset 不一定提供完整来源信息。某些设置的消费者需要新会话或重启才重新初始化。

终端排查可使用以下命令；**这些命令不是无副作用的文件查看器**，omp 的初始化可能迁移自身配置、创建元数据或打开原生数据库：

```sh
omp config path
omp config list --json
# 命名 profile：
omp --profile work config path
omp --profile work config list --json
```

不要批量执行 `config get` 导出所有值或分享完整输出：显式 get 和 set 的输出可能包含秘密。不要把界面的脱敏标记写回真实配置。

### 路径与环境

通常默认配置在 `~/.omp/agent`，文件会话在 `~/.omp/agent/sessions`，但这不是所有安装的固定路径。`OMP_PROFILE`（以及兼容变量 `PI_PROFILE`）、`PI_CONFIG_DIR`、默认 profile 的 `PI_CODING_AGENT_DIR`、原生 `.env` 与符合原生条件的 XDG data/state/cache 根目录都会影响实际位置。命名 profile 有独立原生根目录；不能通过设置桌面主题来切换 profile。

应在桌面与终端使用一致的工作区、profile 和环境。不要仅凭目录名反推出历史项目路径；会话头部的 `cwd` 才是原生记录。存在的工作区和会话文件按真实路径统一身份，避免 `/var` 与 `/private/var`、符号链接或登记路径别名重复分组/打开；不可用工作区保留原路径，不凭空授予访问。读取偏好时的归一化不是改写原生会话头。不要复制实际认证或历史到测试目录来制造验收数据。

## 5. 历史与搜索边界

侧栏索引原生普通 JSONL、gzip 归档及已登记的外部会话路径；逐来源错误/上限诊断与可用结果同时保留。标题、工作目录与首条用户消息预览采用有限读取；**侧栏搜索不是所有历史正文全文搜索**。嵌套 subagent transcript 从父任务查看，不作为独立主会话混入列表。

无法读取的历史来源集中为侧栏底部的一行计数和“重试”。展开可查看来源文件名及简短原因；完整路径保留在提示与可选中复制的路径栏中，详细列表独立滚动，不挤占会话导航。启动错误已显示在会话启动说明中时，不再叠加相同错误的通知。

- 自定义 `--session-dir` 或未登记外部位置不保证自动发现；使用明确的会话文件选择入口。
- SDK 注入的 SQL/Redis 等替代存储不在本桌面的本地 JSONL 历史索引范围内。
- 新建空会话可能尚未落盘；原生采取惰性持久化，内存里已有路径不等于文件已经存在。
- 列表预览不是模型上下文重放；只读正文按已保存分支显示，可保留 clear/压缩前的历史并标记摘要。它不迁移源文件，也不推断未保存的原生内存状态。真正续写的上下文、分支执行与旧格式迁移仍由 omp 负责。
- 不手工编辑正在使用的 JSONL；不要同时从两个进程写入同一活动会话文件。
- 历史正文保留所选祖先链的压缩摘要、reset/clear 前后记录；树每页最多 1,000 节点，可加载更早条目。大于 100,000 条目的历史仍按祖先链分页，不用原始源码视图冒充完整聊天。索引使用可丢弃的临时 SQLite 元数据，不是第二套 Agent 会话权威存储。异常尾行、不可用资源及上限显示诊断；超大单条记录可分段查看来源细节。
- gzip 历史只读流式读取；移动记录中的 `previousSessionFiles` 是来源线索，不拼接成另一条消息时间线。明确从归档 fork 时先受限暂存解压内容/资源，再由真实 omp 创建新会话并核对完整性，临时目录随后清理；原压缩文件保持不变。
- 历史加载/分页失败保留已可读内容并提供明确重读入口；不会混合不同来源版本的分页。来源、分页及读取限制不是原生模型上下文限制。

## 6. 文件、附件、差异与 subagent

文件面板是工作区内的**只读浏览/预览**，不是 PI 插件文件编辑器、内嵌浏览器或任意本机文件服务。主进程检查真实路径，限制符号链接越出工作区。文本、图片存在读取大小限制；二进制或过大文件有明确不可预览状态。

从聊天中的本地文件链接打开嵌套文件后，点击“返回文件”（Back）会展开其父目录，在文件树中定位并聚焦该文件；重新打开同一文件 tab 不重置已有目录树和搜索状态。

当前读取限制：UTF-8 文本 2 MiB，按签名识别的 PNG/JPEG/GIF/WebP 图片 10 MiB，代码预览最多 5,000 行。文件搜索查路径而非正文，跳过 `.git`、`node_modules`、`.venv`；最多遍历 10,000 项、返回 500 个结果，触及边界保留已有结果并显示部分结果诊断。`src/foo` 将搜索范围缩到 `src/`；空查询显示有限根文件与引导。目录树不列出符号链接。

附件经原生文件选择、拖放或明确粘贴的图片字节授权后读取。剪贴板接受经签名核对的 PNG/JPEG/GIF/WebP，单图最多 10 MiB；剪贴板来源没有磁盘路径，不伪造文件授权。普通文字粘贴保留换行，不把 HTML 当成聊天标记执行。外部附件授权不开放整个外部目录。发送前检查是否含秘密或不应外发内容；发送后的信息不能靠删除 chip 撤回。

待发送附件最多 24 个、总计 32 MiB，授权有效期 30 分钟，并限定真实工作区。保存的是授权时快照；过期显示原因并要求明确重新添加，不自动从磁盘重读。主进程只在提示词受理后消费附件 ID；发送失败保留草稿，发送期间的新编辑不应被旧请求完成时清空。fork 转移草稿/附件也不代表已发送。

差异面板展示**当前 Git 工作区差异**，不是某条 Agent 消息专属的编辑记录。它可能包含用户或其他进程的修改；不是 PI 的可逆快照，不提供假回滚。无工作区、无 Git 仓库或无差异时应显示相应空状态/原因，不把没有数据当成修改成功。

Git 查询区分 staged/unstaged；未跟踪文件只标注存在，不伪造 patch。只读调用不启用 external diff/textconv，最多处理 200 个变更文件；单次命令输出与合并 patch 都限制为 4 MiB，超限显式失败而非静默省略。
Git 卡片按文件名/目录显示状态、staged 或 worktree 标记及增删统计；展开后按 hunk 显示新旧行号与增删行，而不是整块原始 patch。无换行、二进制或过大预览有对应说明；删除条目不提供不存在的“当前文件”入口。预览仍只读，没有暂存、撤销或回滚按钮。

### 内联委派与子代理详情

- 每次 `task` 调用在对话原位置显示“委派 N 个子代理”，不需要先展开过程。任务开始创建时先显示待开始条目，随后更新为原生状态；状态文字、分段进度、实时耗时和已有工具/token 指标一起呈现，运行时可看到最近活动。
- 点击已登记的子代理行打开侧面详情；详情显示同一身份的状态、耗时、指标和对话，当前详情对应的内联行高亮。卡片底部“原始调用”可展开参数/结果；不能定位到当前可见调用的子代理集中在末尾“其他子代理”，不重复排列已锚定的任务。
- 点击卡片标题可展开/收起。超过 3 个子代理的批次在全部结束后自动收起；手动切换后不再覆盖你的选择。展开时较多已完成条目可通过“另有 N 个已完成”继续查看。动画遵循系统“减少动态效果”，状态不只靠颜色表达。
- 工作面板启动页在存在子代理时显示带数量的“子代理”（Subagents）入口，打开按委派分组的总览，再点行进入详情。子代理、文件、Git 和资源 tab 使用不同图标；同名子代理详情加序号区分。总览不是第二套执行或调度入口。

Subagent 由 omp 创建和调度，不是桌面第二套任务管理器。活动详情通过原生 transcript 接口，采用 UTF-8 **字节游标**而非字符偏移；原生只保留已登记的活动/近期 transcript。保存的 task 子会话则按父会话和具体 tool call 只读发现，不为查看历史重新启动 RPC 或任务。子会话有独立正文分页、错误/任务说明、提醒折叠和来源诊断；缺失/歧义来源保留已保存元数据，不冒充完成或可恢复实时状态。

**原生状态限制：** omp 18.3.2 将子代理 `yield(error)` 上报为 cancelled，界面显示“已停止”并保留原因，不改写为成功或强行标成失败。真实窗口验收未覆盖红色失败徽标；停止场景不能证明该徽标已验证。

保存输出/恢复区域在工作面板独立资源 tab 中只读分页，每页 64 KiB，提供加载、失败重试和前后页；按父来源及不透明引用定位，保留页游标与阅读位置。文本使用代码/原文呈现，不通过 Markdown 触发外部资源加载；支持的栅格图片可预览，二进制/缺失资源明确标记。历史内联图片与按需打开都受来源授权和字节上限约束，缺失图片不会隐藏可见正文。子任务发现和资源扫描有限额，可能只列出部分旧任务，必须结合诊断理解。

## 7. 原生 RPC UI 的明确限制

支持的是原生 RPC 表达的标准选择、确认、单行输入、编辑请求、通知、状态与文本 widget。原生扩展的任意 TUI 组件、自定义 header/footer/editor 工厂、终端输入钩子、自动补全提供者组合和 TUI 主题控制不能直接转成桌面组件。遇到仅终端支持的扩展界面，应在终端 omp 使用；桌面不能静默批准或用成功占位代替它。

审批/输入对话框显示所属会话/工作区及原生请求的绝对本地截止时间；未给超时的请求不显示倒计时。排队不重新起算截止时间，超时回答由运行时 store 统一发送，不能因弹窗重挂载延长期限或重复回答。

**omp 18.3.2 的启动扩展限制：** 在 `session_start` 中同步等待 UI 回答可能因原生启动分发顺序阻塞而在 30 秒后超时，即使匹配的回答已经写入 stdin。独立、不经过桌面的诊断已复现；桌面不修改原生代码、注入批准或伪造成功来绕过。正常运行会话中的 ask/select 已实测通过，这不是所有原生对话框的共同限制；详细时间证据见 [VERIFICATION.md](VERIFICATION.md)。

原生 RPC 没有通用 `list_sessions`、文件补全或全量设置 CRUD/schema 接口。桌面的历史索引、工作区补全与 config CLI 适配是明确的本机展示边界，不应被理解为另一个 Agent 内核。

传输同样有明确界限：物理帧 1 MiB、v2 重组帧 64 MiB，初始化消息总量 128 MiB；超限会报错，不会把截断结果当成完整历史。原生请求/模型/OAuth 不设桌面强制完成期限或自动重试；发现可执行文件的探测和退出时清理则有界。

## 8. 安全与故障处理

- 渲染器不直接获得 Node、原始 IPC 或任意命令执行接口；外链经过主进程协议检查。不要通过关闭 Electron sandbox 来解决环境问题。
- **渲染器沙箱不是 Agent 工具沙箱。** omp 及其原生扩展以当前用户权限执行工具，可能修改工作区、运行命令或访问网络。只打开可信项目，按原生能力配置权限并审阅交互。
- 本地桌面不等于模型离线：服务商请求、原生工具和扩展可能联网并产生费用。
- Markdown 的 HTTP(S) 图片可内联加载，会向远端服务器发出请求；使用 no-referrer 不等于匿名或离线。HTTP(S) 音频/视频提供内联播放控件，采用 `preload=none`，并校验 URL、拒绝 URL 内嵌凭据、清理嵌套 source；播放失败后才提供外部打开入口。这不等于提供 PI 插件浏览器。
- 找不到运行时：检查安装、可执行文件路径与 GUI 环境；不要指定一个仅名字类似 omp 的任意程序。
- 无模型/认证失败：用同一 profile 在终端完成真实配置，确认服务商可用后重新建立会话。
- 设置保存后未变化：检查覆盖来源和当前工作区/profile；不要反复覆盖整个配置文件。
- 历史为空：核对 profile、原生实际根目录、自定义会话位置与是否已落盘，不要将空列表直接解读为数据丢失。
- 停止/退出异常：保留脱敏错误与时间，区分原生错误、传输错误和窗口状态；桌面不自动重发用户请求。
